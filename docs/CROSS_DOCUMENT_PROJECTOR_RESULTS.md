# 跨文档投影器验证结果

日期：2026-10-08  
分支：`feat/pisco-joint-query-projector`，验证代码 `2150191`，协议见 [`CROSS_DOCUMENT_PROJECTOR_VALIDATION.md`](CROSS_DOCUMENT_PROJECTOR_VALIDATION.md)。

**结论：顺序对齐后，SQX−SQ 的 bridge 差值两个 seed 都为正，但均值只有 +0.35 F1pp（CI [−0.31, +1.01]），没有达到预定的 +0.5 门槛。阶段 C 按用户决定作为探索性实验运行：S0X−S0 接近零，所有对比的 CI 都跨零。普通文档级跨文档 attention 没有建立稳定的 QA 收益。**

## 1. 设置

| 臂 | query 条件分支 | 跨文档 attention | 参数（M） |
|---|---|---|---:|
| S0 | 无 | 无 | 33.59 |
| S0X | 无 | 有 | 34.64 |
| SQ | 真实问题 | 无 | 37.78 |
| SQX | 真实问题 | 有 | 38.83 |

- 各臂从发布版 PISCO 独立初始化；冻结 compressor、decoder/LoRA；K=10、m=8、D0、答案 CE。
- 3000 步，lr=5e-5，线性调度，5% warmup，batch 2 × accum 8。
- `--data_order_seed` 等于模型 seed；四臂只在 `--projector_query_mode` 和 `--projector_cross_document` 上不同。
- 评估：dev 前 2000 题（bridge 1622，comparison 378），统一用 **last** checkpoint；训练中 dev500 的峰值不作为结果。
- CI：以题目为单位的配对 bootstrap；跨 seed 均值先对每题平均再重采样。CI 不包含训练 seed 的随机性。

**顺序对齐核验**：同一 seed 下四臂 step1 的 `train_order_digest` 和 loss 完全相同（seed42：`1b6aef…`、5.1079；seed43：`5c74b9…`、3.9509），step0 dev500 F1 都是 16.7。分析脚本 audit 对两个 seed 都报告 `matched_training=true`，且无缺失训练记录字段。

## 6. 解读

1. **不带 query 的跨文档 attention 在本配置下没有可测收益。** S0X−S0 全部 +0.06、bridge −0.02，两个 seed 都接近零。
2. **SQX−SQ 的 bridge 差值方向一致，但幅度小于旧单 seed 结果。** +0.35 对比旧的 +0.73，CI 跨零。顺序对齐与 seed 方差都可能造成这一缩水，本轮无法区分二者。
3. **交互项为正但不确定。** bridge 交互 +0.36 与 SQX−SQ 的 +0.35 几乎相同，因为 S0X−S0 约等于 0。两个 seed 差距大（全部题型 −0.15 / +0.69），CI 跨零。它不能证明 bridge 收益来自 query 与跨文档结构的联合作用。
4. **SQX−S0X 是两个 seed 方向一致、幅度最大的对比**（+0.63 / +0.41，均值 +0.52 [−0.17, +1.19]）。它说明有跨文档 attention 时，query 分支至少没有失效；但 CI 跨零，不构成确立结论。
5. **SQ−S0 在 dev 上的 seed 方差很大**（+0.79 / −0.29），说明单 seed 下约 1 F1pp 的差值仍在训练噪声范围内。

## 7. 不支持的说法

- 不能只拿 seed43 的 SQX−SQ +0.68 当方法收益：只给 SQX 挑 seed、SQ 不挑，属于单侧选择。两边都取最好 seed 时，整体差值为 64.69 − 64.42 = +0.27。seed43 SQX 可以作为部署模型，但论文中应同时报告两个 seed。
- 不能宣称跨文档 attention 学会了桥接实体或多跳推理。
- test 已被历史实验多次查看，不能当作未见 holdout。新的外部证据需要来自未参与设计的多跳数据集（如 MuSiQue）。

## 8. 下一步依据（协议第 6 节）

普通 SQX 没有稳定收益，按协议本轮不再遍历 attention 深度或超参，也没有对这批 checkpoint 运行完整 test。若继续跨文档方向，候选是更具体的结构：

- 让第一跳的桥接实体或状态进入第二跳的 query（参照 DecompRC、MDR）。先用正确第二跳子问题做 oracle 测试，再决定是否训练。
- 实体或文档对关系约束（参照 HGN），以普通 SQX 为必须超过的基线。

若需要把 SQX−SQ 的估计做实，可补 seed44/45 的 SQ/SQX（四卡并行约 1.8 小时）。

### 解读

1. **query 分支在 TriviaQA 上小幅为负**：SQ−S0 −0.78，两个 seed 同负，与 HotpotQA 专训 test 上的 +0.37 方向相反。
2. **跨文档 attention 在 TriviaQA 上为正**：两组 X−非X 都在 +1.2 至 +1.6，CI 不跨零。
3. **这部分增益主要落在错配文档地板上**：X 臂地板高约 3.5 EM（约 62 对 58.6），证据值反而从约 9.6 降到约 8。更可能是闭卷能力或答题格式保留得更好，而不是证据利用更好；此解释未验证。
4. TriviaQA 证据可争空间只有约 9 分（与 HANDOFF 的 8.8 一致），这里的差值不宜外推到多跳任务。
