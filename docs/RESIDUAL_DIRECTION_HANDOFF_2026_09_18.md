## 1. 用户确定的首要目标

**从已有 PISCO 基线出发，先确认质量平齐，再争取超过基线。让主创新点产生正常问答质量收益。**

当前不继续以几个较弱方案之间的小幅差异作为主要进展；不把 D4/D5 的低分重新解释成忠实性优势。先做有效的系统，再安排主要消融和机制分析。

长期研究方向仍是：在冻结、可复用的文档压缩表示上做 query 条件化处理。当前先保留全部 latent，隔离新增处理带来的收益或损失；若取得质量收益，再研究缩减输出预算。这个阶段不声称二次压缩或实际加速。

## 2. 本轮对实验结果的共同理解

### 2.1 C1 > S 可作为继续研发的依据

HotpotQA dev 2000 题，单 seed，固定 query 表示、B=8：C1 43.10 EM，S 37.50 EM，差值 +5.60。暂不把进一步证明 KD 的收益路径作为研发前置任务。

S 的余弦 top-B 没有可训练参数；S+KD 更新的是 decoder LoRA。C1+KD 则同时更新 readout 与 decoder LoRA。“S 加 KD 后平均 EM 相同”不等于模型没有变化，也不能推出 KD 的收益只能经过 readout。保留方法优于 S 的观察，暂缓这项机制归因。

### 2.2 D0/D4/D5 与 P 的数据必须说清楚

| 设置 | decoder 输入 | 正常 EM | 错配文档 EM | 差值 |
|---|---|---:|---:|---:|
| P，D0 | 全部文档 latent + 明文问题 + 模板 | 54.50 | 21.80 | 32.70 |
| C1，D0 | 8 个读出向量 + 明文问题 + 模板 | 43.10 | 22.55 | 20.55 |
| C1，D4 | 8 个读出向量 + 6 个问题向量 + 模板 | 32.90 | 5.55 | 27.35 |
| C1，D5 | 文档读出向量 + 问题向量，去掉模板 | 32.85 | 5.35 | 27.50 |

来源：当前 `results/arm_matrix.json`。这里的 P 是仓库中的全缓存直喂基线，**它已经做过错配文档实验**，不是指 PISCO 原论文做过这项实验。20.55、27.35 是两种输入干预下的 EM 差值，不是正常准确率。

错配文档仅是辅助诊断：错误文档可能主动误导模型，不能把差值直接称为精确的证据信息，也不能将错配得分当成参数记忆的精确贡献。不要求每轮调参都跑错配，更不能以差值变大替代主指标变好。

D4/D5 当前正常问答质量显著较弱。它们的近似持平不能证明删 system prompt 对 P 免费，也不能证明“问题不可压缩”。本轮暂停这条支线。

### 2.3 投稿竞争力与归因分开推进

- 当前首要攻关目标：正常输入下超过实际 P baseline。
- 超过 P 说明新系统有质量竞争力；query 条件化的独立贡献以后仍需参数匹配等消融。
- “相近质量、明显更低实际成本”仍可能有价值，但目前质量差距较大、在线加速也未测出，不以此替代提点。
- P/S 同样能缓存复用。文档缓存不是 QuRO 独占优势。
- 压缩输入的学生不必然受一个实际教师模型准确率的严格上限约束；P 不是理论最优读出。但残差、蒸馏都不能保证超过 P。

## 3. 已决定实施的残差方案

借鉴残差参数化：保留一个已经工作的映射，让新模块学习修正。

```
E = Z + Delta_theta(query, Z)
loss = CE(decoder(E, query), gold_answer)
```

没有人工给定的“正确残差”标签；修正由最终答案损失学习。也没有证据证明 QuRO 旧方案的失败就是 ResNet 讨论的深度退化问题，不能将类比当成已定位机制。

**与旧 C1 的区别：**旧输出是注意力混合后的向量加修正，初始化时已损失/混合信息；新输出在 Delta=0 时保留 P 的每一个原始 latent、有效 mask 和顺序。

已实现的 R 臂：

1. 读取 `hp2d0_P/config.json` 与 `checkpoint_last.pt`，继承数据/缓存/backbone 配置，加载实际已训练的 P decoder。
2. 保留全部有效 latent（Hotpot 通常最多 80 个）、D0 明文问题和 PISCO 模板。
3. 修正分支默认 256 维：每个 latent 对 query 做 cross-attention，再对 latent 序列做 self-attention，包含 FFN。
4. 输出投影零初始化；恒等旁路不加归一化、缩放或投影，初始严格 E=Z。无需另加零门控。
5. 第一轮默认冻结 P decoder 与真实 generator query encoder，只训新增分支；保留 decoder 对输入的梯度，不能把训练 decoder 前向整个放进 no_grad。
6. 不使用 KD、不使用 query dropout、不增加辅助损失。初始恒等不保证训练后保持或提升质量。

## 4. 第一步为什么不要求先修 KL

此前顺序 1 包含“修好 KD 数值问题”。这不是本轮 CE-only 残差实验的前置依赖。

- **现在只用 CE：**不进入 KD 路径，可直接开始。
- **以后重新启用 KD：**必须先修复 `src/distill.py` 中 FP32 的 `1-1e-9` 舍入至 1 导致 tail log 不稳定的问题，并完成 teacher cache 对齐验证。

本轮没有声称 KL 已修好。新增的是一般性保护：非有限 loss/梯度时停止训练，避免静默更新污染参数。

真正必要的前置检查是初始 P 等价、梯度可达、冻结状态正确以及 checkpoint 保存恢复一致。这些是实现检查，不是要用户先跑一大轮论文消融。

## 5. 下一位执行者：按此顺序运行

### 步骤 A：同步代码，核实源 baseline

在服务器现有仓库中检查工作区状态，保留未提交工作；拉取并切换 `feat/pisco-identity-residual`。如果已经合并 main，则使用包含上述实现和本文的 main。

确认 `/data02/quro/runs/hp2d0_P` 中存在 config、checkpoint、对应结果及数据缓存。54.50 来自具体运行，不能仅凭公开 PISCO 权重路径就声称加载了这个 baseline。脚本支持 `BASELINE_RUN` 覆盖源目录。

### 步骤 B：先复现初始平齐

```bash
CUDA_VISIBLE_DEVICES=0 bash scripts/run_pisco_residual.sh init
```

- 自动小批检查：soft tokens、mask、答案 logits 和 CE 与同一个 decoder 下的 P 一致，否则停止。
- 完整 dev 评测：核对是否重现源 P 的 54.50 EM，以及逐题预测、F1、输入长度和评测样本。
- 若未对齐，先查源 checkpoint、数据/分词器/生成配置、精度和加载路径；**不要通过调参掩盖初始不一致**。
- 自动两条样本检查通过不等于完整 Hotpot 结果已经复现。

### 步骤 C：第一轮只训练修正

```bash
CUDA_VISIBLE_DEVICES=0 bash scripts/run_pisco_residual.sh train
```

默认 3000 步、CE-only、冻结 decoder。保留训练曲线，按固定开发子集 EM 选择 best；完整默认结果仍是 last，必须明确报告评测哪一个 checkpoint，不把 500 条子集最优数当成 2000 条主结果。

先看正常问答 EM/F1 是否超过加载的 P。若有收益，记录幅度与逐题变化，再复验稳定性。若退化或无收益，检查残差参数是否实际更新、训练/验证曲线与修正幅度，再决定调整；暂不盲目堆损失、扩大网格或回到 D4/D5。

### 步骤 D：需要 decoder 共同适配时再做

```bash
CUDA_VISIBLE_DEVICES=0 bash scripts/run_pisco_residual.sh joint
CUDA_VISIBLE_DEVICES=1 bash scripts/run_pisco_residual.sh p-control
```

两者从同一 P checkpoint 出发，匹配新增训练步数、样本与优化设置。若只超过旧 P，却不超过继续训练的 P，不能把收益归因于新增 R 模块。这是公平比较，不是当前要铺开的消融矩阵。

以上每次新运行使用独立 TAG；脚本拒绝覆盖已有输出。长任务在服务器现有持久终端会话运行。未经上述证据，不写“已经平齐/超过”的完成状态。

### 步骤 E：有质量收益后再拓展

再研究 B=32/16 等预算缩减、query 条件化消融、多 seed 与实际在线成本。Gold 文档控制和支持文档覆盖诊断保留为遇到瓶颈时的工具，不作为当前第一轮启动的强制前置任务。

## 6. 完成后应上传什么

- 新运行完整配置、代码 commit/工作区差异、源 P checkpoint 的可追溯信息。
- 训练和验证曲线，明确 best/last；正常输入下 EM、F1、substring 和实际 token 数。
- 小批恒等检查结果，以及初始 R 对 P 的完整评测核对。
- 可复核的逐题预测与配对统计，条件允许时记录在线时延；没有测过的指标留空。
- 一段明确判断：初始是否平齐、训练后是否超过旧 P/匹配继续训练的 P、下一步只改什么变量。
