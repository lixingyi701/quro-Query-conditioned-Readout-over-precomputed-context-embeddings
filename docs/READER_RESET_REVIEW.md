# 2026-10-02 修订：先修正监督定义，不再用结构试跑替代研究判断

本文件取代旧 recovery 下一步，以及本分支前一提交 `1537c92` 的四臂残差读取 pilot。
**撤回“4×300 步、超过 CE/MLP 1pp 才继续，否则暂停冻结 Z 路线”的执行建议。**
`direct-read` / `direct-mlp` 代码保留便于复现，但不再是默认训练任务；本修订不新增结构。
服务器数值来自用户汇报及仓库已有结果记录；本地没有重新运行真实 PISCO 或声称读过服务器原始日志。

## 1. 前一轮错误在哪里

1. **没有把用户提出的发布版起点列为主对照。** P₁ 已在项目 Hotpot 30k 上训练约 3000×16 次样本呈现。再次从 P₁ 对同一数据训练，同时引入优化器重启、学习率和样本重复，研究问题被混在了一起。P₁ 首次适配有效，不能因此成为所有后续方法的唯一入口。现在发布版入口不加载 P₁ 配置或权重，P₁ 仅保留为强域内参考。
2. **把代理量的改善当作方法依据。** 原 State 是答案前最后一个 prompt 位置的三层 `[B,3,H]` 全向量余弦对齐；它既不是答案序列分布，也不是某段文档对答案的贡献。更接近教师隐藏态没有保证 QA 更好。
3. **W 同时破坏了已经工作的证据接口。** 将原 80 个 Z slots 换成 16 个随机 W，零初始化 CA，起点没有 Z 贡献，却期待短答案 CE 同时学好新接口和 decoder。这缺少必要的机制依据。
4. **上个修订仍未解决监督问题。** 删除 State、改回 gold CE、追加答案侧 CA，改变的是结构。不能把它称为“监督已经修好”。给这一结构加小预算和停止规则，也不会使其更有科学依据。

这些是实验设计与论证的错误；不能用“研究总会失败”替代对它们的纠正。

## 2. 现有数据支持什么，尚不能支持什么

| 已有证据 | 可以说 | 不能说 |
|---|---|---|
| 同起点 300 步，1e-4 明显退化，1e-5 近乎稳定 | 高学习率是已测早期退化的重要因素 | 低 LR 解决了所有泛化问题；1e-5 是发布版起训最优 LR |
| 低 LR 3000 步，两臂后期 QA 下降、NLL 上升 | 继续优化这个配方未获得持续收益 | 已因果证明“重复数据过拟合”是唯一原因 |
| State 在旧固定128样本上普遍比 CE 更近教师，低 LR QA仍无增益 | 旧状态目标有效改变几何，但未证明任务价值 | 所有功能性蒸馏无效；增加 lambda 一定有效 |
| 加权梯度比约0.3–1.0，平均梯度余弦接近0 | 没有明显“State 完全被压没”的证据 | 0.1 刚好最优；所有 batch 都不冲突；低 LR 梯度比例必然相同 |
| W错配 Z 几乎不变，关闭 CA QA轻降、NLL反而改善 | 已测 W 对证据内容的特异性利用很弱 | CA 完全无作用；所有读取器都不能利用 Z |
| 含答案段替换成 raw 恢复大部分差距 | 主要误差与含答案段的压缩/读取有关 | 已证明 Z 中信息丢尽，或反过来已证明 Z 保留了可恢复答案 |

数据中的小处也应纠正：低 LR 第500步 State=.634、CE=.632，并非“500步以后始终不高于 CE”。这不改变整体没有可靠正收益的判断。
降低 LR 通常同时缩小两项梯度产生的更新，并不会自动把 lambda=0.1 调到最优；Adam 的逐坐标缩放又使范数比不等于最终更新比。本阶段不继续旧全向量 cosine 的 lambda 扫描。

低 LR best 的 State−CE = −0.4pp，CI [−1.2,+0.4]，只描述既定模型在这500题上的配对不确定性，不能代替 seed 不确定性。相同 dev 上选 best 后再算 CI 有选择偏差。NLL变差与substring略升也可能并存，应分别报告。

## 3. 接受含答案段定位，不重跑已取消的位置研究

`READER_CAUSAL_ORDER_RESULTS.md` 已记录：

- P₁ dev2000，D0=.600、raw=.678；发布版 D0=.4865、raw=.607。
- K=2 仍存在缺口，因此不是仅由多余文档干扰产生。
- 在1193道“两个 gold 段中恰有一个含答案”的 bridge 子集，P₁ 只换含答案段为raw恢复约71%的缺口，发布版约100%；只换bridge段收益很小。

因此应优先研究**含答案段的任务信息如何从 Z 被利用**，而不是笼统说“多跳组合能力差”并叠加结构。
不过这是一项 K=2、特定子集的输入干预结论，不等于 K=10 全训练分布上的教师标签已可用。新审计不再做位置扫描；只回答将这个定位用于训练时，是否实际产生可用监督。

## 4. 本次确实修改了什么监督

PISCO 论文 §3.2/§4.3 使用教师生成序列的 SKD；其消融中，原数据短标签 SFT 在 needle 检索上有退化，移除 SKD 也降低 QA。它还报告不同教师的输出质量有区别。[论文](https://arxiv.org/html/2501.16075v1)

这提供“应优先核查任务输出监督”的依据，**不证明本项目的退化原因已经找到**。原 P₁ 与继续训练文件都没有 teacher 字段，排除的是这两阶段间的目标切换；没有证明 gold CE 与发布版原训练目标等价。

新代码保留发布版 D0、原冻结离线 Z、原 decoder LoRA。训练时仅更换序列目标：

\[
\mathcal L_{seq}=-\sum_t \log p_\theta(\tilde y_t\mid Q,Z,\tilde y_{<t}).
\]

不再对三层整向量加 cosine；没有新 lambda。教师是冻结的发布版 decoder，先用四种输入视图自由生成：

| 视图 | 输入 | 用途 |
|---|---|---|
| M | 全部原 Z | 已有压缩输入参考 |
| R | 全部对应 raw 段，逐段同样截到128 tokens | 普通 raw-output SKD 基线 |
| A | 只将含答案段换为 raw，其余原 Z | 与已定位缺口直接对应的候选教师 |
| B | 只将bridge段换为raw，其余原 Z | 判断 A 的作用是否具有角色特异性 |

保持原 K、文档顺序、query、模板和截断规格。A/B 只用于角色明确的训练 bridge 样本；不把答案拼进prompt。学生训练和推理始终看到全部原 Z，没有 oracle 选段。

教师独立自由生成，记录 substring/EM/F1、EOS、长度；另做 gold teacher-forced逐token NLL，拆出不含EOS的内容 NLL。后者是诊断，不作为训练 loss，也不把 teacher-forced命中冒充生成答对。
教师通过 substring、EOS与长度筛查才使用其文本，否则退回 gold。substring不能证明解释忠实，必须检查 `teacher_audit.jsonl` 的实际例子。脚本不自动启动训练。

导出同题、同序、同原Z的四份文件：

- `gold.jsonl`：清除旧 teacher 字段，普通 gold CE。
- `raw_skd_all.jsonl`：所有通过筛查的 R 输出；普通 SKD 主基线，不局限于候选有利的题。
- `raw_skd_matched.jsonl`、`answer_skd_matched.jsonl`：仅在 R/A 都通过筛查的共同集合换目标，其余相同 gold。候选与普通教师的差异只能在共同集合比较。

**SKD 是已知基线，不是新创新。** A 教师是与定位结果一致的研究假设；它会减少一部分教师/学生输入差异，但也可能比 R 弱，或产生完全相同的短答案。不能提前宣布其优越性、新颖性或给它一个方法名字。
此外这不是完整复现 PISCO 原训练：原方法联合训练 encoder/decoder、使用原始教师；这里冻结缓存，使用发布版decoder的raw视图。比较范围仅限当前缓存式读取任务。

## 5. 为什么还需要少量验证，以及它不能替代什么

撤回“小规模训练不赢，就暂停整条路线”。新的默认动作是**不更新参数的训练目标审计**，随机512道训练题，不是 dev 前512，不是重新寻找模型分数。

它有三个明确产物：

1. 在实际 K=10 训练输入上，A/R是否修复M错误，A与B有何差异；样本数量和CI一起保留，不用人为1pp门槛裁决。
2. 教师正确、完整、可用于训练的比例；与gold及彼此的**token相同率**。若全部相同，目标数学上等价，代码拒绝重复训练。不同token也只是必要条件，格式变化本身不是新任务信息。
3. 人能读懂的原题、gold、角色、四份输出、逐token NLL，判断是否只是答复更长、复制答案或产生错误解释。

这些检查解决“监督是否实际存在、质量如何”的缺失信息。它们**不能证明 Z 可恢复性、不能证明泛化收益、不能据此停止整个冻结Z方向**。若有效子集很少，512题的CI会宽；此时应报告数量限制，而不是不断追加扫描或把结果判负。

同样不能把 A→学生的成功仅解释成“答案证据被读取”：训练记忆、格式迁移、样本难度仍可能影响结果。真正方法结果需要未见题上的 matched 对照与证据干预。

## 6. 后续投入的顺序与边界

本次交付只把监督审计与真实训练入口做完整，不自动排 GPU 作业。运行命令见 [监督运行说明](ANSWER_EVIDENCE_SUPERVISION_RUNBOOK.md)。

1. 发布版权重/缓存与原 D0 harness 的零步行为一致。发布版是主起点，P₁ 不再作为默认二次训练起点。保留原80 slots，不冻 decoder 去硬训另一个随机接口。
2. 清理 train/tune/dev 重叠；用未参与原30k训练的训练池题建立 tune。原dev已反复看过，只作探索记录。发布版上重用本项目30k，不等于从P₁对它重复适配；也不能保证发布版上游从未见过相关数据。
3. 审计教师目标，并检查真实输出。若R与gold等价，先承认这个SKD实现没有新信号；不启动等价臂，也不据此推出冻结Z不行。若R目标有价值，先做发布版 `gold CE vs raw_skd_all`，识别普通任务蒸馏能解释多少收益。
4. 只有R/A提供不同且可信的目标，才有理由运行共同样本集合上的 R vs A。相同初始化、问题顺序、优化器、批量、调度与种子；报告目标长度/监督token数差异，不能声称同题数即同计算量。
5. LR与停止日程在新tune上为普通基线确定，再锁定用于相应方法比较。P₁上1e-5稳定不等于发布版最优；也不为候选挑best却固定一个弱CE。小于完整训练的smoke只验证实现；300步失败不裁决整个路线。
6. 如建立可复现收益，再用冻结配方、多seed和真正未使用的留出题确认，并检查答案段证据干预下的收益来源。不要在反复看过的dev上把1–4题的波动说成创新成功。

若 A 不优于 R，结论是“局部教师没有超过普通SKD”，不是把普通SKD的收益算为新方法，也不是Z无法读取。若任务目标充分、实现正确、优化充分后仍无泛化增益，当前候选缺乏支持；是否改压缩器需要另一项可恢复性证据与明确成本讨论，不自动换故事。

**现在能回答的信心边界：** 旧监督不充分、上一版结构提案未修复它、发布版基线应优先，这些有清楚依据。新目标能否超过强CE，当前没有真实模型结果，不能保证。现有资料也不足以证明“冻结Z一定能补回raw差距”。前者可由目标审计和受控训练进一步回答，后者无法由一次小规模阴性结果证明。
