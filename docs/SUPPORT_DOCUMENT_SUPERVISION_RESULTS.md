# 支持文档辅助监督首轮结果（2026-10-03）

**一句话结论：** 支持监督对 QA 是零收益。SQ+Doc 比匹配的 CE 续训 SQ+Head 高
+0.07 F1 [−0.16, +0.29]，没有达到方案里事先定的成功条件。辅助头确实学会了挑出
gold 文档（Recall@2 从 0.20 升到 0.55），但几乎没有用到问题：给投影器换一个错误
问题后，Recall@2 不变，86% 的题选出的前 2 篇文档集合不变。投影器对问题的依赖也
没有变强（换问题的掉分两臂相同）。

设计和判据见 [SUPPORT_DOCUMENT_SUPERVISION.md](SUPPORT_DOCUMENT_SUPERVISION.md)，
上一轮结果见 [SHARED_QUERY_PROJECTOR_RESULTS.md](SHARED_QUERY_PROJECTOR_RESULTS.md)。
代码：`feat/pisco-joint-query-projector@2375fb9`。运行输出在
`/data02/quro/runs/support_doc_v1/`（启动脚本与日志在 `logs/`）。本文所有表格由
`python scripts/analyze_support_supervision.py` 生成，原始输出存于
`all_tables.txt`。

## 1. 两个臂到底是什么

**共同设置**（两臂只有 λ 不同）：

- **起点**：上一轮 SQ 主臂（`shared_projector_v1/shared_contextual`）第 3000 步的
  last checkpoint，只加载权重（`--warm_start`），optimizer 和学习率调度重置。
- **SQ 的结构**：冻结发布版 PISCO-Mistral（encoder、decoder、两组 LoRA 全冻结），
  HotpotQA K=10，每篇 8 个缓存 memory，共 80 个。问题单独过一遍冻结 decoder，取
  所有问题 token 的最后一层 hidden；每篇文档的 memory 用 8 头 cross-attention 读
  问题，进每篇共用的残差 MLP（隐藏层 512），输出 `E_i = Z_i + Δ_i`，替换 D0 模板
  输入层的 memory 位置。投影器 37.78M 参数，详见上一轮结果文档第 1 节。
- **新增辅助头**：`support_logit_i = Linear(LN(u_i))`，`u_i` 是该篇文档的 512 维
  MLP 隐藏状态，只加 513 个参数。两臂都创建这个头（`--support_head`），所以初始化
  和参数量完全相同。生成答案时不计算这个头，decoder 的输入路径和 SQ 一样。
- **续训**：1000 步，lr 2e-5，5% warmup 后线性衰减，每步 16 条（batch 2 × 累积 8），
  seed 42，单 seed。每 100 步在 dev 前 500 条上验证，按 F1 选 best。
- **数据**：train/dev 用带可见性注释的版本
  `/data02/quro/data/hotpot-support-visible/`，题目、文档和顺序都和原始数据相同。
- **评估**：dev 全部 2000 条，**last checkpoint（续训第 1000 步）**，贪心解码，
  最多 32 个新 token。没有评估 test。

**两臂差异：**

| 代号 | 目录 / tmux / GPU | 辅助损失权重 λ | 辅助头 | 训练目标 |
|---|---|---|---|---|
| **SQ+Head** | `sq_ce` / `sd_sq_ce` / GPU0（独占） | 0 | 存在但收不到梯度，保持随机初始化 | 只有答案 CE |
| **SQ+Doc** | `sq_ce_doc` / `sd_sq_ce_doc` / GPU1（独占） | 0.1，前 100 步从 0 线性升到 0.1 | 用平衡 BCE 训练 | 答案 CE + 0.1 × 支持文档 BCE |

SQ+Head 用来排除"额外训练 1000 步"本身带来的收益，所以**主比较是 SQ+Doc −
SQ+Head**。下文也列出上一轮的 SQ（不续训）和 S0m（不看问题的对照）作为参照。

**辅助损失的标签**：`gold_ranks` 里的文档（每题 2 篇）是正例，其余 8 篇是负例，
每篇独立 sigmoid。每题对正例和负例分别取均值再等权平均。可见性策略是 `visible`：
如果一个正例的支持句没有一句完整落在编码器实际看到的前 128 token 里，这个正例就
被屏蔽，不参与损失，也不会被改成负例。

**控制条件**：mismatch-q 只给投影器（含辅助头）换成别的题的问题，decoder 仍看
正确问题；文档识别指标仍按原问题的 gold 文档计算。

train 中 29730 题（99.1%）同时有可用的正例和负例，参与辅助损失。

- 编码器模板和发布版 `prepare_encoder_inputs_to_decoder` 一致：`<ENC><bos>文档<eos>`，
  右截断到 128+3。
- 抽查 train 前 3000 题的 6000 个正例，支持句 100% 能在文档原文里找到，不存在因
  字符串匹配失败把正例误判为不可见的情况。
- 续训第 0 步 dev 前 500 条 F1 0.643，与 SQ last 一致，说明 warm-start 加载正确；
  随机头的 Recall@2 是 0.18，接近随机水平 0.2。

| 指标 | SQ+Head（头未训练） | SQ+Doc | SQ+Doc，投影器换错误问题 |
|---|---:|---:|---:|
| Recall@2 | 0.200 | **0.552** | **0.554** |

| Recall@2，只看两篇 gold 都可见的题 | 0.209 | 0.571 | 0.569 |

## 6. 分析与观察

1. **QA 零收益。** 主比较 +0.07 F1，区间以 0 为中心且很窄（±0.23），按题型和
   可见性拆开也都是 0。按方案的判据，"CE+Doc 的 QA 超过匹配 CE 续训"不成立。

2. **头学会了分类，但靠的是文档本身，不是问题。** Recall@2 从 0.20 升到 0.55，
   both@2 从 0.02 升到 0.24，分类任务确实学会了。但换成错误问题后指标完全不变，
   logit 相关 0.93，86% 的题选出的前 2 篇不变。也就是说，头主要在判断一篇文档
   "像不像 HotpotQA 的 gold 文档"。可能的原因是：HotpotQA 的干扰文档是按问题
   检索出来的，在实体类型、篇幅或写法上可能和 gold 文档有系统差异，单看文档就能
   分出一部分。这个原因本轮没有验证。

3. **辅助梯度没有推动问题和 memory 的交互。** 换问题的掉分两臂相同（1.11 对
   1.16），所以加了支持监督后，投影器对问题的依赖没有变强。这和第 2 点一致：
   最容易降低辅助损失的做法，是用和问题无关的文档特征，而 512 维的共享隐藏状态
   里本来就有这类特征。

4. **额外训练量本身可能有小收益。** 只用 CE 续训 1000 步，相对 SQ 有 +0.59 F1
   [−0.06, +1.29]，接近显著。设 CE 续训对照正是为了把这部分排除。它和 S0m 比是
   +0.48，同样不显著。

5. **对后续方向的含义。** 方案写的是"文档识别上升但 QA 不变时，再讨论是否把相关性
   接到残差门控上"。本轮的头几乎不依赖问题，接到门控上，等于给投影器加一个和问题
   无关的文档先验，这和要检验的"问题条件化"假设无关，所以不建议直接接。结合上一轮，
   在冻结发布版 PISCO、只训投影器的设定下，问题信息能带来的作用稳定在约 1 个 F1
   点，这一轮的监督信号也没有把它放大。

## 7. 局限

- 单 seed（42），只续训了 1000 步，λ 只试了 0.1。
- 只评估了 dev 2000 条，没有评估 test 和 best checkpoint。
- 头的结构很小（单个线性层），只接在 `u_i` 上；"不依赖问题"是这个结构和这个 λ
  下的结论。
- 第 6 节第 2 点关于 gold 文档和干扰文档系统差异的解释未经验证。一个直接的检验是：
  训练一个完全看不到问题的分类器（例如 S0m 的隐藏状态，或直接用 Z），看它能否达到
  相近的 Recall@2。
- 评估时为了计算文档识别指标，每个 batch 多做了一次投影器前向，这部分时间不能算作
  部署时延。
