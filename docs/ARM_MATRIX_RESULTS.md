# 臂矩阵结果：TriviaQA 与 HotpotQA

> 日期：2026-09-17
> 数据：[`results/arm_matrix.json`](../results/arm_matrix.json)（25 次运行、16 组配对检验，含每次运行的 commit）
> 生成：`python scripts/collect_arm_matrix.py`
> 范围：3000 步，seed 42，冻结 PISCO 缓存 + 冻结 Mistral + decoder LoRA。**单 seed。**

本文汇总三轮实验：修正对照定义后重跑的 TriviaQA 四格矩阵、转到 HotpotQA 多跳之后的完整基线对比（含 S 与 P），以及 B ∈ {8,16,32} 的预算扫描。

---

## 0. 三十秒版本

1. **历史上所有 A 臂其实是 A1。**磁盘上每个 A 臂都带 `cosine_prior: True`，余弦先验是 query 进入 readout 的第二条独立通路，`--output_query_mode agnostic` 关不掉它。真正的 A0 从未跑过，"比 query 无关版高 20.85 分"这句话当时没有对照组。
2. **补齐四格后，干活的是可学习读出，不是余弦先验。**两个数据集一致：**在 B=8 上**余弦先验叠加在可学习读出之上没有边际贡献（B 增大后不成立，见第 7 条）。
3. **换 HotpotQA 是对的。**TriviaQA 的证据可争夺空间只有 8.8 分，HotpotQA 有 20~23 分。
4. **可学习读出赢了 0 参数的余弦规则。**TriviaQA 上 S 领先，HotpotQA 上 C1 赢 5.20 分（p=7.7e-08）。这是本项目最该证明的一件事，它成立了。
5. **但 PISCO 原方法（P）在 D0 上赢 C1 11.70 分**，而 prefill 只从 156 降到 75（2.08×）。**这个交换在当前实验规模下不划算。**
6. **加预算买不回来。**B 从 8 扫到 32：C1 饱和在 46.80（距 P 仍差 7.70），而 **S 在 B=32 反超**。可学习读出的优势是**低预算下的现象**。
7. **第 2 条结论只在 B=8 成立**：余弦先验在 B=32 上贡献 +6.75（p=8.0e-14）。见 §3.1 的更正。

## 1. 臂的定义

query 有两条独立通路进 readout。历史实验只动了其中一条，所以只有两格。

| 臂 | 余弦先验 | query 进 output slots | 隔离出什么 |
|---|---|---|---|
| A0 | 关 | 关 | 真正 query 无关的读出 |
| A1 | 开 | 关 | 仅余弦条件化 |
| C0 | 关 | 开 | 仅学习式条件化 |
| C1 | 开 | 开 | 完整方法 |
| S | 余弦 top-B，无可学习槽位 | | 非参数读出 |
| P | 全部缓存 latent 直喂，不二次压缩 | | 上游方法本身 |

定义在 `config.ARMS`，用 `--arm` 启动；`arm_label()` 把**实际实现的臂**写进 `result.json`，所以标错的启动会在结果文件里现形，而不是只留在启动脚本里。

`S` 的"0 参数"只描述读出规则——它的 decoder LoRA 照样训练。

## 2. 主表：HotpotQA，D0 分布内（qdrop=0）

这是标准设定，问题明文在 prompt 里。n=2000（dev），floor 指常数基线。

| 臂 | soft token | prefill | D0 EM | D0 sub | 错配文档 EM | **证据值** | **证据/token** |
|---|---:|---:|---:|---:|---:|---:|---:|
| **P** | 80 | 156 | **54.50** | 59.80 | 21.80 | 32.70 | 0.41 |
| **C1** | 8 | 75 | 42.80 | 46.35 | 22.75 | 20.05 | **2.51** |
| S | 8 | 75 | 37.60 | 41.15 | 24.55 | 13.05 | 1.63 |

配对 McNemar（n=2000）：

| 比较 | Δ EM | p | Δ sub | p |
|---|---:|---:|---:|---:|
| **C1 − S** | **+5.20** | 7.7e-08 | +5.20 | 1.6e-07 |
| **P − C1** | **+11.70** | 4.4e-30 | +13.45 | 6.7e-39 |
| P − S | +16.90 | 1.0e-53 | +18.65 | 6.2e-64 |

**怎么读这张表：**

- **C1 赢 S 5.20 分。**可学习读出在多跳上确实值钱。TriviaQA 上 S 是赢的（71.70 vs 70.90），换数据集后翻盘。
- **P 赢 C1 11.70 分。**二次压缩到 8 个 token，在多跳上代价是 11.7 个 EM 点。
- **prefill 只省 2.08×，不是 10×。**prompt 开销（system + 问题 + 分隔符）约 70 个 token 是大头，soft token 从 80 降到 8，总长只从 156 降到 75。**11.7 分换 2× prefill，不划算。**
- **证据值比 EM 更能说明问题。**错配文档下 P 还有 21.80、C1 还有 22.75——这部分不是证据带来的。扣掉之后，P 用 80 个 token 榨出 32.70 分证据，C1 用 8 个榨出 20.05 分：**C1 的每 token 证据效率是 P 的 6 倍。**

## 3. 四格分解：余弦先验 vs 学习式条件化

均为 qdrop=1.0 训练（训练时问题明文从不在 prompt 里，soft token 是 query 的唯一通道），D1 评测。

### D1 EM

| | 学习式**关** | 学习式**开** |
|---|---:|---:|
| **TriviaQA** | | |
| 余弦关 | A0 = 0.40 | **C0 = 27.75** |
| 余弦开 | A1 = 5.90 | C1 = 26.75 |
| **HotpotQA** | | |
| 余弦关 | A0 = 10.45 | **C0 = 30.55** |
| 余弦开 | A1 = 12.70 | C1 = 31.15 |

### 分解

| 差值 | TriviaQA | | HotpotQA | | 含义 |
|---|---:|---:|---:|---:|---|
| | Δ EM | p | Δ EM | p | |
| **C0 − A0** | **+27.35** | 6.7e-158 | **+20.10** | 4.9e-82 | 学习式条件化**单独**的贡献 |
| A1 − A0 | +5.50 | 7.5e-27 | +2.25 | 2.0e-03 | 余弦先验**单独**的贡献 |
| **C1 − C0** | **−1.00** | **0.27 n.s.** | **+0.60** | **0.53 n.s.** | 余弦叠加在学习式之上：**无** |
| C1 − A1 | +20.85 | 1.8e-96 | — | | 历史报告的那个数字 |

**三条结论：**

1. **干活的是可学习读出。**C0−A0 在两个数据集上都是最大项，而且 C0 单独就追平了完整方法 C1。所以增量不是一个 0 参数的余弦规则披了层网络。

2. **历史的 20.85 既低估又归因错误。**它的对照 A1 已经通过余弦先验漏了 5.5 分 query 信息进去。真实的"query 条件化的价值"是 C0−A0 = 27.35。

3. **在 B=8 上，余弦先验叠加在学习式之上没有贡献**（两个数据集：−1.00 / +0.60，均 n.s.），而它每次在线查询要付一次 7B 的 query 编码：**实测 A0（两条路全关）的训练步速比其余三臂快 36%**，就是这笔钱。

   **⚠ 不要据此撤掉它——见 §3.1。**B=32 时它贡献 +6.75（p=8e-14）。它在 D0 上也有用（TriviaQA C1−C0 = +2.40，p=5e-4）。

   它当初的理由是**初始化论证**——随机初始化下 xattn 的 logits 太小，softmax 变成平均而不是选择（实测 99.85% 均匀熵）。那只说 step 0。跑满 3000 步后 C0 追平了，**它可能是训练加速器而非必需组件**。

**A0 在 D1 落在地板是结构决定的，不是发现。**D1 删掉问题明文，A0 又关掉两条 query 路，系统里没有任何地方存在问题信息。它的作用是管道检查：证明 A0 真的 query 无关。（TriviaQA A0 = 0.40 对地板 0.35；HotpotQA A0 = 10.45 对地板 0.10 则明显高于地板，说明 10 篇候选里有 2 篇 gold 时，静态池化也能带进一些可抽取的答案。）

### 3.1 更正：上面那条结论只在 B=8 成立

B 扫描之后必须收窄第 3 节的第 3 条。**余弦先验的贡献随预算急剧变化：**

| | C1 − C0 | p |
|---|---:|---:|
| B=8（TriviaQA / HotpotQA，qdrop=1.0） | −1.00 / +0.60 | n.s. |
| **B=32（HotpotQA，qdrop=0）** | **+6.75** | **8.0e-14** |

机制上说得通，`readout.py` 本来就写着：没有排序先验时所有槽位会挤到同一个 latent 上（实测槽间余弦 1.000，B−1 个预算浪费）。8 个槽位挤一挤损失有限，32 个就是灾难。

**所以"余弦先验无边际贡献、可以撤掉"这句话是错的**，它只描述了 B=8。正确表述：*在 B=8 这个工作点上余弦先验无边际贡献；预算增大后它变得必要。*

## 4. B 扫描：加预算买不回那 11.7 分

HotpotQA dev，D0，qdrop=0，**固定单预算**（`FIXED_BUDGET=1`，关闭预算 dropout）。

固定预算是必须的而非更整洁：混合预算下 slot 按批内最大 B 生成、小预算事后遮掉，而 slot self-attention 没有预算掩码，所以同批的 B=8 行产出的不是它单独运行时的结果。用混合批扫 B 测到的是这个污染，不是预算（W5）。`hp2d0_*` 那几个共享预算的运行**不能**当这条曲线的锚点，B=8 在此重跑。

| 臂 | B | prefill | D0 EM | sub | 错配文档 | 证据值 | 证据/token |
|---|---:|---:|---:|---:|---:|---:|---:|
| C1 | 8 | 75 | 43.35 | 47.20 | 22.85 | 20.50 | **2.56** |
| C1 | 16 | 84 | 45.85 | 49.95 | 23.15 | 22.70 | 1.42 |
| C1 | 32 | 102 | 46.80 | 51.15 | 23.90 | 22.90 | 0.72 |
| S | 8 | 75 | 37.20 | 40.70 | 25.10 | 12.10 | 1.51 |
| S | 16 | 84 | 43.10 | 47.00 | 23.35 | 19.75 | 1.23 |
| **S** | **32** | 102 | **47.25** | 51.85 | 21.90 | 25.35 | 0.79 |
| C0 | 32 | 102 | 40.05 | 43.05 | 25.00 | 15.05 | 0.47 |
| **P** | — | 156 | **54.50** | 59.80 | 21.80 | 32.70 | 0.41 |

**C1 − S 随预算逐点收敛：**

| B | Δ EM | p | Δ sub | p |
|---:|---:|---:|---:|---:|
| 8 | **+6.15** | 5.5e-10 \*\*\* | +6.50 | 1.6e-10 \*\*\* |
| 16 | +2.75 | 5.5e-03 \*\* | +2.95 | 3.5e-03 \*\* |
| **32** | **−0.45** | **0.67 n.s.** | −0.70 | 0.49 n.s. |

**三条结论：**

1. **预算不是瓶颈。**C1 的边际收益 `B8→16 +2.50`、`B16→32 +0.95`，已经塌了。B=32 距 P 仍差 7.70 分，而 prefill 102 对 156 只省 1.53×。再加预算没有意义。

2. **S 在 B=32 反超。**C1 饱和而 S 稳步爬升（`+5.90`、`+4.15`）。**可学习读出的优势限于低预算区间**——预算宽裕后，余弦挑得差不多就够了。HANDOFF §2 的转向条件（"复杂 C 与 S 接近且更贵则优先简化或重定位"）**在 B=32 这个点上成立**，在 B=8 上不成立。

3. **证据值才是真正的诊断量：**

   ```
   C1:  B=8 20.50 → B=16 22.70 → B=32 22.90    卡死在 ~23
   S :  B=8 12.10 → B=16 19.75 → B=32 25.35    还在爬，且已超过 C1
   P :                                 32.70
   ```

   **C1 预算翻 4 倍只多榨出 2.4 分证据**，而同预算的 S 榨出 25.35，比 C1 还多。同样的文档里躺着 32.7 分可提取证据（P 证明了这一点），我们只拿到 23 分——**丢了约 30%，且丢在一个与预算无关的地方。**

   C1 的错配文档地板（23.90）还高于 P（21.80），说明它比 P 更依赖非证据来源。

## 5. 为什么 TriviaQA 是最不利的场

| | TriviaQA | HotpotQA |
|---|---:|---:|
| D0 错配文档地板 | **57.6 – 59.4** | **11.95 – 15.45** |
| C1 的证据可争夺空间 | 8.80 | 21.65 |
| C0 的证据可争夺空间 | 7.20 | 23.25 |

7B decoder 在 TriviaQA 上闭卷就拿 59 分，在 HotpotQA 上只有 13 分。**所有方法在 TriviaQA 上争的只有 8.8 分的空间**，而余弦 top-B 已经把大部分拿走了——这才是 D0 下 C≈A≈S 挤成一团的真正原因。不是方法无效，是题目没给证据留位置。

推论：**TriviaQA 上的 null 结果，说明的东西比它看起来少。**单事实问答一条 latent 就答完，另外 B−1 个槽位无事可做，多槽位读出没有结构性理由赢余弦 top-B。

**任何 D0 精度数字旁边必须有错配文档地板。**没有地板的精度数字无法解读。

## 6. 机制：余弦 top-B 为什么在多跳上垮掉

按题型分层（HotpotQA，qdrop=1.0，D0）：

| 题型 | n | C1 | S | **C1 − S** |
|---|---:|---:|---:|---:|
| **bridge**（需要桥接实体） | 1622 | 34.77 | 20.28 | **+14.49** |
| **comparison**（两实体都在问题里） | 378 | 47.09 | 41.27 | **+5.82** |

**差距在 bridge 上是 comparison 的 2.5 倍**，方向和幅度都符合事先的预测：

- **bridge 问题的第二跳文档与 query 的表面相似度天然很低**——这正是 "bridge" 的定义：得先从第一跳文档找到桥接实体，才能连到第二跳。余弦 top-B 按单个 latent 与 query 的相似度打分，会系统性漏掉第二跳。
- **comparison 问题两个实体都在 query 里明写着**，余弦两篇都能找到，所以差距小。

排除混淆：yes/no 只占 112/2000，剔掉后 span 题上 C1 35.43 vs S 22.40，结论不变。

**待验证**：用 `scripts/check_attention_targeting.py` 直接测各臂对**两篇** gold 的覆盖率。若能观测到 S 的槽位集中在第一跳文档上，这个解释就从"符合预测"升级成"直接观测"。HotpotQA 的两篇 gold 只有 21% 相邻，所以该脚本已改用 `gold_ranks` 显式记位置。

## 7. D1 与"soft token 能否独自携带 query"

| | D0 | D1 | D1/D0 | D0 证据值 | D1 证据值 |
|---|---:|---:|---:|---:|---:|
| TriviaQA C1 | 68.20 | 26.75 | 39% | 8.80 | **26.40** |
| HotpotQA C1 | 37.10 | 31.15 | **84%** | 21.65 | **27.80** |

（均为 qdrop=1.0 训练。）

HotpotQA 上 D1 只比 D0 低 5.95 分。但**这不是 D1 变强了，是 D0 的虚高没了**：TriviaQA 的 D0 里 59.40 分来自闭卷，只有 8.80 来自证据，所以 D0−D1 那 41 分主要衡量的是"问题明文让模型能调用参数记忆"，而不是"soft token 传不了 query"。

按证据值看，**两个数据集上 D1 的证据贡献都高于 D0**。一个可能的解释是 D0 下模型能靠问题明文与参数记忆作答、不必好好用 soft token，D1 下被迫使用。

**但这个对比不能从当前数据下结论**：这些模型是 qdrop=1.0 训练的，本来就是为 D1 优化的，它们的 D0 是分布外。要检验这一点需要 qdrop=0 下的同臂对比。

**D1 的定位**：即便 D1 追平 D0，省下的只是 prompt 里的问题明文（HotpotQA 上 75→52 token），而在线仍要跑 7B 的 query 编码——那笔钱没省掉，只是换了地方付。且没有真实 RAG 系统部署时会把问题从 prompt 删掉。因此 D1 平价适合作为**核心机制论断**（B 个 soft token 是 (query, evidence) 的充分统计量），不适合当主表。

## 9. 限定

1. **单 seed（42）。**配对检验界定的是同一次运行内的抽样不确定性，**不是 seed 方差**。三个不显著的差值尤其需要多 seed 才能定性：`C1 − C0` 的 −1.00 / +0.60（§3），以及 B=32 上 `C1 − S` 的 −0.45（§4）。后者承担着"S 反超"这个结论，它只是**没有证据说 C1 更好**，不等于已证明 S 更好。
2. **§2 主表与 §4 的 B 扫描不在同一训练协议上。**主表用共享预算（buckets 4,8 + dropout），B 扫描用固定单预算。所以主表的 C1 B=8（42.80）与 bs8_C1（43.35）是两个不同的系统，差 0.55 分，**不要混用**。
3. **B=32 的 C1 曾因一个 NaN bug 全程训废**（`cosine_bias` 在有效 latent 少于 budget 时 topk 取到 −inf，softmax 出 NaN）。表中是修复后重跑的结果。**该 bug 只影响 budget > 最短行有效 latent 数的情形**，B=8/16 的历史结果不受影响，C0/A0 任何预算不受影响（先验关闭时该段直接返回），S 走另一个读出类。值得注意的是前向输出始终有限、只有梯度是 NaN——"形状对、无 NaN"的检查抓不到它。
4. **qdrop=1.0 与 qdrop=0 两列不可比。**前者训练时问题明文从不在 prompt 里，其 D0 是分布外。
5. **qdrop=1.0 的设定对 S 和 P 结构性不利**——它们没有可学习读出，学不会把 query 塞进 soft token。第 2 节的主表用 qdrop=0，不受此影响；第 3、5、6 节的 qdrop=1.0 数字受影响。
6. **HotpotQA 的 EM 比 TriviaQA 严得多**：它每题只有一个 gold 字符串，TriviaQA 有别名列表。**两边数字不能横向比。**
7. **TriviaQA 的 2000 条已被反复查看，是开发数据。**HotpotQA 的 dev/test 已切开，test（5405 条）未动过。
8. **历史 gonogo 运行用的是 mismatch-query 而非 mismatch-doc**，因此没有证据地板，其证据使用量无法追溯恢复。
9. **W3 未修**：query encoder 与 decoder 共用同一个 `lm`，`no_grad` 只挡反传、挡不住权重被答案损失更新，所以"固定 query encoder"与实现不符。本轮所有运行都是这个行为（与历史一致），但各臂可比性存疑。

## 10. 下一步

B 扫描把问题的形状固定下来了，所以这一节相对上一版整个重写。

**已经排除的解释**：预算不够。B 翻 4 倍只多榨出 2.4 分证据（§4）。

**剩下的解释只有两个**，而且能分开测：

- **(a) 读出的输出不是"选择"而是"合成"**——如果输出主要来自 Δ 那条零初始化自由分支，那注意力 α 就不是因果路径，任何针对注意力的改进都打空。
- **(b) 训练信号不足**——唯一的学习信号是答案 CE，要穿过冻结的 7B 才回到 readout；而 decoder LoRA 同时在训，系统可以共同适配到"读出给凑合的证据、decoder 将就"的局部最优。证据值饱和正是这个的表现，C1 的错配文档地板（23.90）高于 P（21.80）也是。

|---|---|---|---|

| 4 | **gold 覆盖诊断** | 把 §6 的机制解释从"符合预测"升级成"直接观测"：S 的槽位是不是集中在第一跳。 | 纯读 checkpoint |
