# 训练数据重设计：p-control 之后该换什么

> 日期：2026-09-18
> 前置：[`RESIDUAL_RESULTS.md`](RESIDUAL_RESULTS.md) 第 7 节
> 状态：**设计讨论，未实现、未运行。**下列数字中，数据规模与缓存重叠率是实测的，训练结果是推测的。

---

## 1. 需要解释的现象

`residual_p-control_s42`：不加任何新模块，只把 `hp2d0_P` 的 decoder LoRA 在同一批 30000 条上再训 3000 步，**EM 从 54.50 掉到 52.90（p=0.044）**。

这条对照原本只是为 joint 准备的公平基准，结果它本身成了本轮信息量最大的一条：**当前配方下，额外训练预算的边际价值是负的。**

在这个前提下讨论"R 为什么没提点"是问错了问题。R 在冻结设定下打平（−0.15，p=0.79），已经是这个优化面上能拿到的最好结果之一。继续调 R 的宽度、blocks 数或学习率，是在一个向下的斜坡上调模块容量。

**两个候选解释，目前无法区分：**

| | 假设 | 若为真的预测 |
|---|---|---|
| H1 | **数据耗尽**：P 已把这 30000 条拟合透，再训即记忆 | 换成 P 没见过的数据，继续训不再退化 |
| H2 | **配方问题**：lr、正则、优化器设置本身不适合续训 | 换数据也照样退化，需改优化设置 |

H1 的检验成本远低于 H2 的调参空间，且下节表明成本低到近乎免费。**先做 H1。**

## 2. 可用数据的实测盘点

### 2.1 HotpotQA：还有 60447 条没用

```
原始 distractor train : 90447 条
当前 train.jsonl      : 30000 条   (prepare_hotpot_data.py --train_questions 30000, seed 42)
未使用               : 60447 条   ← 同分布、同任务、同答案格式
原始 validation      :  7405 条 = dev 2000 + test 5405
```

`test.jsonl` 的 5405 条已建缓存但从未用于训练，**应继续保留为测试集，不要挪作训练**。

**缓存代价（实测，抽样 5000 条未用问题）：**

| | |
|---|---|
| 文档槽 | 49735 |
| **已在缓存中** | **23130（46.5%）** |
| 外推全部 60447 条需新编码 | 约 313k 篇（上界，未计跨样本去重） |
| 编码耗时 | **约 19 分钟**（实测 68 doc/s/卡 × 4 卡） |
| 磁盘 | 约 +20 GB（当前 17.1 GB / 260236 篇，/data02 余 396 GB） |

`doc_id_for` 是内容哈希（`sha1(text.strip())[:20]`），语料全局去重，所以**现有缓存条目全部继续有效**，只需增量编码新文档。这是目前所有备选里代价最低的一个，差一个数量级。

### 2.2 selecom / gonogo：98000 条，缓存已建好，但不能直接用

`/data02/quro/data/gonogo/`，`source: selecom-stage1/stage2`，缓存在 `/data02/quro/cache/gonogo-pisco-r16`（33 GB，已建）。

**它已经被用过**——`gonogo_P_D0` / `gonogo_C_D0` / `gonogo_S_D0` / `gonogo_A_D0` 都跑在它上面，不是一批被遗忘的数据。

不能直接并进 HotpotQA 训练的原因是**答案格式**：

| | gonogo | hotpot |
|---|---|---|
| 答案样例 | `"During the 1660s under Asad Khan Luni."` | `"Jim Obergefell"` |
| 答案长度 | 平均 7.3 词，中位数 6，p90 10 | 短 span |
| 精确 yes/no 占比 | 7.4%（实测；`stats.json` 的 `yes_no_fraction=0.4301` 口径不同，以实测为准） |
| 每问文档数 | 平均 6.0（4 干扰） | 10（8 干扰） |
| 语料 | 261356 篇，**独立 cache 目录** | 260236 篇 |
| 既有 P 臂 dev EM | **17.0%** | 54.50% |

那 17% 不是模型差，是 EM 对着 6 词生成式答案基本无法得分。**把它混入训练会把 decoder 往长答案分布上拉，而评测仍在 hotpot dev 的短 span 上，是净损失。**

可考虑的用法（均未验证）：作为第一阶段预训练数据后接 hotpot 微调；或先做答案归一化/重标注再混合。两者都比 2.1 复杂，**不建议作为第一步**。

### 2.3 顺带记录：缓存阶段丢掉了 26% 的文档内容

```
[cache] mean fed tokens/doc 110.6 (untruncated 149.2, truncation loss 25.9%)
```

证据在被压缩之前就已经截掉四分之一。这与 [`quro-evidence-headroom`] 关心的"证据可争夺空间"直接相关，是一条独立的、与本文数据问题正交的线索。**本文不展开，但不应遗忘。**

## 3. 建议的实验设计

### 3.1 首选：让 R 训练在 P 没见过的数据上

这是 2.1 的一个特殊用法，比单纯"扩大训练集"更干净：

```
decoder (冻结)  ← 已在 train[0:30000] 上训练完成
残差分支 R      ← 训练在 train[30000:90447]，P 从未见过
评测            ← dev 2000（不变）
```

**为什么这个设计好：**

- decoder 是冻结的，它无法记忆新数据 → 新数据的全部信号只能经由 R 吸收。
- P 在这批新数据上没有"已拟合"优势，H1 若成立，这里应当出现 R 的正收益。
- **不需要重训 P**。baseline 仍是 `hp2d0_P` 的 54.50，与本轮及历史结果完全可比。
- 恒等初始化仍然成立，起点仍是精确的 54.50。

### 3.2 必须同时跑的对照

| 运行 | 目的 | 没有它会怎样 |
|---|---|---|
| **p-control（新数据）** | P 的 decoder LoRA 在同一批新数据上训同样步数 | 无法区分"R 有用"与"新数据本身就有用" |
| **R（旧数据）** | 即本轮 `residual_train_s42` | 已有，作为数据变量的对照点 |

这构成 2×2：{R, P} × {旧 30000, 新 60447}。本轮已填两格，再补两格即可把"模块贡献"和"数据贡献"分开。

**H1 的判决条件：**新数据上的 p-control 若不再退化（EM 回到 54.50 附近或更高），H1 成立，数据耗尽是真因；若照样掉 1.6 分，H1 被否，问题在优化配方（H2），届时才轮到调 lr 与正则。

### 3.3 保持不变的量

- dev 2000 条：**不动**，这是所有历史数字的锚。
- test 5405 条：**保留**，不得用于训练或调参。
- budget=80（全部 latent 不截断）、D0、CE-only、seed 42、3000 步、lr 1e-4：先只动数据这一个变量。

### 3.4 先修掉的测量问题

本轮暴露的：`[val]` 的 500 条子集比全量容易 1.9 分（P 在子集上 56.40，全量 54.50），直接对比会产生假阳性（详见 [`RESIDUAL_RESULTS.md`](RESIDUAL_RESULTS.md) 第 5 节）。

两个选项：把 val 子集扩到 2000 与全量一致；或在日志里同时打印源 baseline 在同一子集上的分数作为参照线。**后者更省算力。**

## 4. 暂不做的

- **调 R 的超参**（宽度 256、blocks 1、lr）：在确认优化面方向之前无意义。
- **KD / KL**：`src/distill.py` 中 FP32 `1-1e-9` 舍入至 1 导致 tail log 不稳定的问题**仍未修复**，且 teacher cache 对齐未验证。修复并验证之前不启用。（`hp2d0_P/teacher_train_T2.pt` 已存在，64 MB。）
- **从未收敛的 decoder 起步**：能给 R 留出空间，但基线随之变弱，"超过一个弱 P"的说服力低于"超过 54.50"。留作 3.1 失败后的备选。
- **预算缩减、多 seed、在线时延**：按交接文档，有质量收益后再谈。

---

## 5. 一句话

下一个变量是**训练数据**，不是模块。最便宜的动作是把 HotpotQA 剩下的 60447 条拉进来（约 19 分钟缓存、约 20 GB 磁盘），让冻结的 decoder 配一个训练在它没见过的数据上的残差分支，并配一个同数据的 p-control 来判决 H1。
