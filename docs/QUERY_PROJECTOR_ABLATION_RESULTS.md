# SQ − S0 主消融结果：去掉 query 分支后少多少（2026-10-06）

**一句话结论：** 彻底去掉 query 条件分支（S0）只让 QA 少约 0.4 F1，且尚未确立。
全量 test（5405 条）上两个 seed 平均的 SQ − S0 是 F1 +0.37 [−0.01, +0.74]、
EM +0.29、substring +0.34，两个 seed 方向一致（+0.31、+0.43）；dev 上 +0.33
[−0.29, +0.96]，两个 seed 一正一负。效应集中在 comparison 题（test +1.24
[+0.23, +2.30]），bridge 题约 +0.14，基本为零，而原文与压缩 memory 的缺口恰恰全部
在 bridge 题上。投影器带来的大部分提升与问题无关。

设计与协议见 [QUERY_PROJECTOR_ABLATION.md](QUERY_PROJECTOR_ABLATION.md)，前一轮
结果见 [QUERY_MODULATED_FUSION_RESULTS.md](QUERY_MODULATED_FUSION_RESULTS.md)，
共享投影器首轮见 [SHARED_QUERY_PROJECTOR_RESULTS.md](SHARED_QUERY_PROJECTOR_RESULTS.md)。
代码：`feat/pisco-joint-query-projector@e4fbff8`。运行输出在
`/data02/quro/runs/query_ablation/`（启动脚本与日志在 `logs/`，分析输出在
`analysis.txt`）。

## 1. 两个臂

| 代号 | query mode | 结构 | 可训练参数 | 是否运行问题编码 |
|---|---|---|---:|---|
| **SQ** | `conditioned` | `u = GELU(h + b)`，b 来自每个 memory 槽对问题 token 的 cross-attention | 37,782,016 | 是 |
| **S0** | `none` | `u = GELU(h)`，没有 Q/K/V、`context_proj`、固定条件向量 | 33,587,712 | 否 |

两臂都是 `E_i = Z_i + reshape(W_o u_i + b_o)`，`W_o` 零初始化，decoder 都收到正确问题
和全部 80 个 memory（D0 模板）。冻结发布版 PISCO-Mistral（encoder、decoder、两组
LoRA），HotpotQA K=10，每篇 8 个缓存 memory。

**共同设置**：两臂都从发布版 PISCO **独立训练**（不从训练后的 SQ 关闭 query），
3000 步，lr 5e-5，batch 2 × 累积 8，只用答案 CE，`--projector_fusion none`，无支持头、
无跨文档 attention；与原 SQ 运行（`shared_projector_v1/shared_contextual`）的训练参数
完全一致。seed 42 和 43 各一对，四个任务各占一张 GPU。主分析用 **last checkpoint**。

| 任务 | 目录 / tmux / GPU |
|---|---|
| SQ seed 42 | `sq_s42` / `qa_sq_s42` / GPU0 |
| S0 seed 42 | `s0_s42` / `qa_s0_s42` / GPU1 |
| SQ seed 43 | `sq_s43` / `qa_sq_s43` / GPU2 |
| S0 seed 43 | `s0_s43` / `qa_s0_s43` / GPU3 |

全量 test 是训练结束后对 last checkpoint 的 eval-only（`fulltest_*`，tmux `qaft_*`）。

**对齐核验**：S0 构造时先按 SQ 的顺序初始化条件模块再删掉，所以同一 seed 下共享部分
的初始化和后续随机数状态相同。实测同一 seed 内两臂第 0 步 dev500 输出相同（EM 0.026 /
F1 0.167）、RMS(h) 相同（s42 0.5768，s43 0.5824），第 1 步 loss 相同（s42 2.7689，与原
SQ 运行一致；s43 3.0077），即样本顺序相同。两臂只差 query 分支。

## 5. 参照与噪声

- **S0 与旧 S0m（固定随机条件向量，seed 42）**：test F1 −0.15 [−0.62, +0.33]，两者
  基本等价，前几轮用 S0m 当无问题对照是可靠的。
- **同 seed 同配置重跑的噪声**：旧 SQ（`shared_projector_v1/fulltest_SQ`）与本次
  SQ s42 配置相同，test F1 却差 0.47 [0.07, 0.90]，528 条预测不同。原因可能是 GPU 运算
  的非确定性，以及中间代码重构改变了计算顺序（数学上等价）。这个噪声与本文的效应
  一样大；本文主比较是同一时间、同一份代码下的配对比较，两个 seed 方向一致，比单次
  比较更可信，但仍不足以确立。
- **同一臂两个 seed 之间**（s43 − s42，F1）：test 上 SQ +0.11、S0 −0.01；dev 上
  SQ +0.25、S0 −0.54。

## 6. 结论

1. **query 分支的总贡献约 0.3–0.4 F1**（约占 65 分的 0.6%）。test 上两个 seed 方向
   一致，CI 下限碰到 0；dev 上不显著。与首轮 SQ − S0m 的全量 test 结果（+0.62）同量级。
2. **效应集中在 comparison 题，bridge 题几乎为零。** comparison 在 test 上两个 seed
   都为正，dev 上一正一负，仍应视为子组结果。原文与压缩 memory 的缺口（P0）全部来自
   bridge 题，而 query 条件化恰好没有作用在那里。
3. **换问题掉分高估了 query 的价值。** SQ 换问题掉 0.45–1.16（随 seed 变化很大），
   都大于 SQ − S0；"给错问题"的伤害大于"不给问题"。mismatch-q 只能说明投影器在读
   问题，不能当作 query 的贡献。这与上一轮 γ 换问题的现象一致。
4. **投影器的提升主要与问题无关。** 从直接读取的约 16 F1 到约 65 F1，几乎全部由
   S0 获得（答案格式与文档本身的变换）。在当前"冻结 PISCO + 每篇 8→8 残差投影器"
   的设计下，query 只多出不到 1 个点。
5. **后续**：如需把"约 +0.4、主要在 comparison"定下来，可补 seed 44（两张卡约 3.5
   小时）。要让 query 产生更大作用，应针对 bridge 这类需要跨文档找证据的题，而不是
   继续改融合方式。
