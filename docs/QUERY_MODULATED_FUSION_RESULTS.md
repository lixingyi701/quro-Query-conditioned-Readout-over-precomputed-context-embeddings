# 问题条件 FiLM 调制对照结果（2026-10-06）

**一句话结论：** 乘性调制没有带来 QA 收益。FiLM − 等容量加法对照（AddG）的 F1 是
+0.04 [−0.18, +0.26]，EM +0.05，substring +0.05，bridge 和 comparison 子集也都是
零；按预定规则不进入 test。两臂都在用问题（换问题掉 1.2–1.3 F1），但 FiLM 并没有
更依赖问题（掉分差 +0.14 [−0.26, +0.54]）。FiLM 实际注入的修正约是加法臂的 5.6 倍，
QA 却相同，所以尺度差异不改变结论。

设计、等容量对照和判据见 [QUERY_MODULATED_FUSION.md](QUERY_MODULATED_FUSION.md)，
上一轮结果见 [SUPPORT_OUTPUT_SUPERVISION_RESULTS.md](SUPPORT_OUTPUT_SUPERVISION_RESULTS.md)。
代码：`feat/pisco-joint-query-projector@58ab32c`。运行输出在
`/data02/quro/runs/query_fusion_v1/`（启动脚本与日志在 `logs/`，分析输出在
`analysis.txt` 与 `fusion_dev.json`，由 `scripts/analyze_projector_fusion.py` 生成）。

## 1. 两个臂

记 `h = memory_proj(LN Z)`（含 bias），`b = context_proj(LN c)`（无 bias），
`γ = tanh(W_γ LN(b))`，`W_γ` 和 bias 零初始化。

| 代号 | 目录 / tmux / GPU | 融合 |
|---|---|---|
| **SQ+HeadE+AddG** | `additive` / `fusion_addg` / GPU3 | `u = GELU(h + b + γ)` |
| **SQ+HeadE+FiLM** | `film` / `fusion_film` / GPU0 | `u = GELU(h + b + γ⊙h)` |

**共同设置**：从 SQ last（`shared_projector_v1/shared_contextual/checkpoint_last.pt`）
只加载权重，optimizer/scheduler 重置；1000 步，lr 2e-5，batch 2 × 累积 8，seed 42，
单 seed；**λ=0**（只用答案 CE），两臂都保留同一个随机、不训练的 output 支持头，
使结构与 HeadE 对齐；数据 `hotpot-support-visible`。两张 GPU 与其他任务共用。

**起点核对**：第 0 步 dev500 两臂都是 EM 0.514 / F1 0.643，与 SQ 一致；第 1 步
两臂 qa_loss 都是 0.1904，数据顺序一致；第 41 步两臂 RMS(γ) 约 0.015，γ 梯度
非零（加法约 0.04，FiLM 约 0.15）。

**与 HeadE 的关系**：HeadE 第 1 步 qa_loss 是 0.1239。新建 `gamma_proj` 时 Linear
的默认初始化先消耗随机数再置零，打乱了数据顺序，所以 HeadE 只能作参照，不是
同顺序对照。

## 3. 交互证据：换问题掉分

只给投影器换成别的题的问题，decoder 仍看正确问题；normal − mismatch-q 的 F1：

| | 全部（n=2000） | bridge | comparison |
|---|---|---|---|
| AddG | 1.16 [0.31, 2.07] | 1.14 [0.30, 1.99] | 1.29 [−1.64, 4.15] |
| FiLM | 1.30 [0.45, 2.24] | 1.38 [0.51, 2.28] | 0.99 [−1.77, 3.79] |
| FiLM − AddG | +0.14 [−0.26, +0.54] | | |

两臂对问题的依赖都显著不为零，但大小相同。错问题与原问题共享答案的只有 4 题。

## 4. 调制量（最终评估，dev 2000）

| | AddG | FiLM |
|---|---:|---:|
| RMS(h) | 4.22 | 4.16 |
| RMS(b) | 1.35 | 1.36 |
| RMS(γ) | 0.065 | 0.099 |
| 实际修正 RMS（加法为 γ，FiLM 为 γ⊙h） | 0.065 | 0.365 |
| 修正 / RMS(b) | 0.048 | 0.269 |

- 由于 RMS(h) ≈ 3.1 × RMS(b)，同样的 γ，FiLM 注入的量更大；训练后 FiLM 的实际
  修正约是加法臂的 5.6 倍，但 QA 相同。"FiLM 能注入更大修正"不能解释出差异，
  因为本来就没有差异。
- 换问题后 RMS(γ) 不变（FiLM 0.0988 对 0.0988，修正 / b 0.269 对 0.267）。这只说明
  调制幅度不随问题变，不说明方向不变；没有测换问题前后 γ 的逐元素差。

## 5. 一个未受控的现象

两臂相对 HeadE 都高约 0.9 F1（dev 2000 配对）：AddG +0.88 [0.04, 1.67]，
FiLM +0.93 [0.08, 1.76]。**不能归因于 γ 模块**：

- 数据顺序与 HeadE 不同，没有控制；前几轮出现过约 1 个点的 dev 波动和 dev/test
  不一致；
- 加法和 FiLM 共有，即使属实也与乘性调制无关。

如需确认，应加一个 γ 冻结为零、随机数消耗与两臂相同的对照臂，或先在全量 test 上
评估 AddG 与 HeadE。

## 6. 结论

1. **按判据，本设置下乘性调制没有初步结构收益。** 限于这个初始化（SQ last 续训
   1000 步）、数据和 λ=0；不否定所有乘性调制。
2. **注入量不是瓶颈。** γ 学了起来，FiLM 修正达到 b 的 27%，但 QA 和问题依赖都
   没有变化。
3. **问题对投影器的作用仍约 1 个 F1。** 连续三轮（hidden 头监督、最终 E 上的头监督、
   FiLM）都没能突破这个量级，说明在当前数据和目标下，瓶颈不太可能在投影器怎么
   融合问题。
4. **下一步候选**：上面约 0.9 点现象的受控核验；或转向同池、换问题、换标签的
   混合池监督与评估，让训练真正要求使用问题。
