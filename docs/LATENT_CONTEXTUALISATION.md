## 1. 第 0 步：memory 位置是被 decoder"加工"，还是只被"读取"？

### 1.1 为什么残差范数本身回答不了

上一轮测到 memory 位置以残差范数 104 进入、以 105 离开，而文本 token 从 0.14 长到 365。
但**范数不等于"没被加工"**：pre-norm 架构里

```
h_{l+1} = h_l + f_l(RMSNorm(h_l))
```

更新量 `f_l(·)` 是从**归一化后**的向量算出来的，它的幅度由这一层决定，与 `‖h_l‖` 无关。
同样一个幅度 O(1) 的更新，加在范数 0.14 的 token 上等于重写，加在范数 104 的槽位上几乎
没有发生。所以要直接测两个量：

- **相对更新** `‖h_{l+1} − h_l‖ / ‖h_l‖`
- **逐层旋转** `cos(h_{l+1}, h_l)`

### 1.2 结果（n=40，Level A，SeleCom 脚手架）

| layer | memory·document | memory·instruction | raw·document | raw·instruction |
| ---: | ---: | ---: | ---: | ---: |
| 0 | **0.0355** | 1.8377 | 1.8912 | 1.8254 |
| 1 | **0.0350** | 1.1275 | 1.0868 | 1.1432 |
| 4 | **0.0557** | 0.6804 | 0.6877 | 0.6781 |
| 8 | **0.0743** | 0.5729 | 0.5688 | 0.5851 |

| 24 | **0.0642** | 0.2765 | 0.3104 | 0.2823 |
| 30 | **0.1310** | 0.4401 | 0.4063 | 0.4442 |
| **0–30 均值** | **0.0709** | **0.5499** | **0.5456** | **0.5551** |

（layer 31 是喂给 LM head 的最后一块，所有条件的更新都在那里暴涨一个量级，因此主干
单独统计。）

**同一条序列里，文本 token 的残差每层被更新 8× 于 memory 槽位（前半段 11×）。**
注意三个对照数字几乎相同（0.550 / 0.546 / 0.555）——**被冻住的不是"document 这一组"，
而是"memory 这种位置"**。

累积旋转（逐层 cos 的连乘，全栈下界）：

| | ∏ cos(h_{l+1}, h_l) |
| --- | ---: |
| **memory · document** | **0.6731** |
| memory · instruction | 0.0135 |
| raw · document | 0.0172 |
| raw · instruction | 0.0128 |

**文本位置走完 32 层后，残差与它的输入 embedding 已近乎正交（cos ≈ 0.014），被彻底重写；
memory 位置仍与写进去的 latent 保持 0.67 对齐。**

reconstruct 指令下同一批数字完全一致（document 0.0709，同样 8×），所以这不是任务效应，
是结构性的。

### 1.3 这句话的含义

> **PISCO latent 以一个使它对各层免疫的幅度插入残差流。它是 decoder 可以
> attend 的只读 K/V 源，但它本身不参与计算。**

这一条把上一轮几个反常一次解释掉：

- **为什么注意力没被"抢走"**：它们从来就只是静态 K/V 源，不是在竞争计算资源的 token。
- **为什么 decoder LoRA 的指令遵循能力不迁移到 memory 通道**（raw +0.65 / memory −0.125）：
  LoRA 改的是残差变换 `f_l`，而在 memory 位置上 `f_l` 的输出相对残差小一个数量级。
- **为什么 α 缩放对两端都无效**：缩放不改变"被读"的方向（attention 走 RMSNorm，尺度无关），
  只改变"被加工"的程度，而后者本来就接近零。

### 1.4 对 R / RQ 零结果的一个候选解释（假设，未验证）

R（残差臂）与 RQ（query-as-Q 写回）都把学到的修正 **写进 memory 槽位**。这确实会改变
**被读到的内容**（attention 经过 RMSNorm，对方向敏感），所以它们不是"改了个没用的量"。

但它们都**无法让 memory 位置参与计算**。如果 memory 相对 raw 的 10.5 点缺口有相当一部分
来自"raw token 经过 32 层组合、后续位置读到的是组合后的表示，而 latent 读到的永远是
压缩当时的那个向量"，那么**任何对静态 K/V 条目的修改都补不回来**——这与 R / RQ 的零边际
一致。

**这是候选解释，不是已验证的因果。** 能检验它的是 §3 的方案 #1：如果把读出写在会被加工的
尺度上确实拿到边际，这条解释成立；如果仍然零，说明缺口在别处。

## 2. 先回答一个必须回答的质疑：decoder 的 LoRA 不就是干这个的吗

PISCO 的 `decoder_adapter` **就是**带着 memory 槽位训练出来的。说"槽位没被加工"听上去像是
在说 LoRA 没起作用。把一层拆开就清楚了：

```
h_{l+1} = h_l + Attn_l(RMSNorm(h_l)) + MLP_l(RMSNorm(h_l))
```

**读路径 — LoRA 确实在调，而且这正是它学到的东西。** 在 memory 位置，LoRA 改
`k_proj/v_proj`，决定这个槽位对外**提供**什么 key/value；在 reader 位置，LoRA 改
`q_proj/o_proj`，决定谁去看它、读到的东西怎么回写。

**写路径 — LoRA 受架构限制，改不动。** memory 位置**自己**的残差怎么演化：

1. RMSNorm 把 `h` 归一化，所以 `f_l(RMSNorm(h))` 的**幅度与 ‖h‖ 无关**，由这一层决定，
   典型 O(1)–O(30)。
2. memory 位置 ‖h‖ = 104。要做到相对更新 0.5，需要 ‖update‖ ≈ 52；同层文本 token
   ‖h‖ ≈ 5、相对更新 0.47，对应 ‖update‖ ≈ 2.4。**LoRA 得在 memory 位置产出比文本位置
   大约 20 倍的更新，同时不能把文本位置炸掉。** 低秩加性扰动做不到这种量级的位置相关放大。
3. **最关键：§1 的 0.071 就是 LoRA 开着量出来的。** 不是"LoRA 还没试过"，是"LoRA 试过了，
   结果是 0.071"。

### 2.1 为什么尺度是正确的旋钮（而不是又一个随手试的超参）

`RMSNorm(α·z) = RMSNorm(z)` —— **读路径对尺度严格不变**。

这解释了上一轮一个当时看着很怪的现象：α 从 0.02 扫到 1.00（50 倍），density / mass /
qk gap 基本是常数。不是测量不灵敏，是**架构上它们就不该变**。

而写路径变了：`h₁ = α·z + u`。α=1 时 ‖α·z‖=104 把 u 淹没；α 小时 u 与 α·z 可比，位置开始
真正演化。

> **尺度是一个只动写路径、不动读路径的旋钮。** 这是 pre-norm 的结构性质，不是巧合。

### 2.2 上下文化到底是不是瓶颈？——bridge / comparison 分层

上面这些只说明 latent 没被加工，没说明**这件事有害**。HotpotQA 的 `hop_type` 提供了一个
免费的判据：bridge 题需要把 A 文档的实体连到 B 文档的事实（**跨文档组合**），comparison 题
只要各自取一个独立事实。

| HotpotQA dev, K=10, n=200 | raw | PISCO memory | 配对差 95% CI |
| --- | ---: | ---: | --- |
| **bridge**（n=161） | 0.615 | **0.478** | **−0.137 [−0.205, −0.062]** |
| **comparison**（n=39） | 0.667 | **0.692** | **+0.026 [+0.000, +0.077]** |
| 全体（n=200） | 0.625 | 0.520 | −0.105 [−0.160, −0.045] |

**10.5 点的压缩代价全部落在 bridge 题上；comparison 题上 PISCO 记忆持平甚至略胜原文。**

这正是"latent 不能跨文档组合"的预测：每篇文档是**独立压缩**的，之后又不演化，所以组合
只能发生在少数几个 reader 位置；而原文 token 可以在 32 层里互相组合，reader 读到的是
**已经组合过**的表示。

注意这条同时说明**问题不是"压缩丢了信息"**——comparison 题上信息显然够用。

## 3. 方案 #1：scale-calibrated readout

**观测 → 动作**：

> 观测到 memory 位置以残差范数 104 进入、每层相对更新仅 0.071（文本 token 0.55，8×），
> 全栈累积旋转 0.67（文本 0.014），且压缩相对原文的全部缺口落在需要跨文档组合的 bridge
> 题上（−0.137 [−0.205, −0.062]，comparison 题为 +0.026）；因此把读出写在一个**使 memory
> 位置会被逐层加工**的尺度上，并与 decoder LoRA 联合训练，**离线 PISCO cache 完全不变**。

### 3.1 α 扫描是它的零训练预览

推理时的 α 扫描直接给出"不训练的话缩放能买到什么"。完整的三元曲线（含上下文化与 QA）
在 §3.3，这里先记住形状：**α 降到 0.5 在文档能力上完全无损**（重建 0.627 略优于 α=1 的
0.616），但相对更新只从 0.071 抬到 0.093，离文本 token 的 0.55 还差一个数量级。

**所以方案成立与否落在一个问题上：训练能不能把低 α 处的文档损失赚回来，并且换来的
上下文化能不能在 bridge 题上兑现。** 没有把握，但有一条明确可证伪的路径。

### 3.2 实现

`ReadoutConfig.output_scale`（+ `output_scale_learnable`），在 `QuROModel.readout_cached`
的最后一步统一施加，因此对每种 readout 一视同仁。

- **`output_scale=1.0` 是逐位相同的 no-op**（`tests/test_shapes.py::test_output_scale`
  用 `torch.equal` 钉死），所有历史 run 仍然可比。
- 只缩放、不旋转——方向是 decoder 读的东西，旋转它就等于同时动了读路径，干预就不再是
  关于上下文化的了（同样有测试）。
- 默认**固定**不可学：固定值是干预；可学的是另一个问题（"训练想不想要 PISCO 的尺度"），
  两者不能混。

### 3.3 分阶段执行与事先定死的判据

**Stage B（无训练，已完成）** — `stageB-alpha-qa`（Level B，HotpotQA dev 200 行，
QA substring + bridge 分层）与 `stageB-alpha-context`（Level A，40 篇，记录相对更新）。

**选择规则（事先定死）**：α\* = 满足"memory 相对更新 ≥ 0.3/层"的**最大** α。

#### 这条曲线说了三件事，其中一件是坏消息

1. **事先定死的规则选不出 α\*。** **没有任何 α 达到 0.3**：最大值是 α=0.05 的 **0.273**，
   而那里文档已经塌了（重建 0.254 ≈ `mismatch` 的 0.126–`none` 的 0.104 一带，
   QA 0.385）。把残差从 104 缩到 5.2 只让 memory 位置看起来像一个**已经过了半个栈的**
   文本 token（文本 token 在第 16–24 层的相对更新正是 0.47→0.28），而不像一个**刚进栈的**
   token。要匹配第 0 层的文本 token 需要 α ≈ 0.14/104 ≈ 0.0013，那里文档只剩零。

   > **单靠缩放，到不了文本级的上下文化，除非先把文档毁掉。**

2. **零训练下缩放在真正的指标上什么也没买到。** α=0.5 是免费的（QA +0.010，重建 0.627
   略优于 α=1 的 0.616，相对更新涨 31%），但**bridge 只从 0.478 动到 0.491（+0.013）**——
   相对 0.137 的缺口等于没动。**缩放本身不是解法**。

3. **但它把上下文化的目标从"不可能"变成"可能"。** 相对更新 = ‖update‖/‖h‖。
   α=1 时 ‖h‖=104、update≈7.4，要到 0.5 需要 update≈52，是 **7×**；
   α=0.05 时 ‖h‖=5.2、update≈1.4，要到 0.5 只需 update≈2.6，是 **1.9×**。
   **1.9× 是 LoRA 可能学到的量级，7× 不是。** 零训练达不到 0.3 不等于训练达不到——
   这正是 Stage C 要测的。

#### α 的选择：规则失效，改用判断（并把判断暴露出来）

事先写下的备用条款是"若没有任何 α 同时满足两条，照样训，但把零训练掉幅写进记录作为
训练必须跨过的基线"。实际情况比预想更差：**主规则（相对更新 ≥ 0.3）本身无解**。

因此 α 的选择**不是事先定死的，是事后判断**，为了不让它变成一个隐藏的自由度，
**两个 α 都跑**：

| 臂 | scale | 相对更新 | 零训练 QA 掉幅（训练必须跨过的基线） |
| --- | ---: | ---: | --- |
| **P₁**（对照） | 1.0 | 0.071 | — |
| **Pa10** | 0.10 | 0.204（2.9×） | **−0.055 [−0.115, +0.005]** |
| **Pa05** | 0.05 | 0.273（3.8×，最接近判据） | **−0.135 [−0.195, −0.075]** |

**Stage C（训练，进行中）** — `scripts/run_output_scale.sh`，三条臂，
`preset=pisco_hotpot`、`steps=3000`、`seed=42`、D0（`query_text_dropout=0`）、
eval 只用 hotpot dev（test 半区不碰）：

```
--arm P --output_scale {1.0 | 0.10 | 0.05} --generator_lora_init pisco
```

三条都用 `P`（`pisco_direct`，**readout 零参数**，实测 `[params] readout: 0.0M`），
所以训练唯一改动的是 decoder LoRA，任何增益都不可能经由"学到的读出"洗出来。

**P₁ 必须重跑，不能用历史数字**：已发布的 P 多数是冻结 decoder 评的，拿它对比一个训练
了 3000 步的 Pα 会把训练的功劳记到尺度头上。

**go/no-go（事先定死）**：
1. hotpot dev substring `Pα − P₁` **≥ +1.5 点**；
2. **且 bridge 子集上的增益 ≥ comparison 子集上的增益**（机制一致性——若尺度只是泛泛地
   帮忙而不是修复跨文档组合，两者应该差不多，那就不支持这套解释）；
3. 训完重测 §1 的相对更新，memory 位置 **≥ 0.3/层**（确认干预真的生效了，而不是只把
   输入缩小了）。

三条都满足 → 方案成立，再把 readout 加回来。
**只满足 3 不满足 1** → 上下文化不是缺口所在，§1.3 的解释作废，但这是有价值的否定结论。
**满足 1 不满足 2** → 有增益但机制不是跨文档组合，必须重新找解释，不能按这套说法写。
**都不满足** → 缩放这条路走完了，转 §6。

**风险（已经比设计时高）**：Stage B 已经表明零训练缩放在 bridge 上什么也没买到，而且
上下文化目标零训练够不着。Pa05 起步就带着 −0.135 的 QA 赤字，训练要先把它填平再产生
+0.015 才算 go。起点也不再是恒等映射——R / RQ 的恒等起点换来了干净但为零的结果，这次
连干净的起点都没有。

#### 判据 ③：训练后相对更新 ≥ 0.3/层 —— **不满足，而且方向是反的**

用各臂训练后的 checkpoint 重测（`--checkpoint`，n=40，layers 0–30，document 组）：

| 在该尺度上测 | 训练前（Stage B） | P₁ 训练后 | 该尺度训练后 |
| --- | ---: | ---: | ---: |
| α = 0.10 | 0.204 | 0.2087 | **Pa10: 0.1759** |
| α = 0.05 | 0.273 | — | **Pa05: 0.2094** |
| α = 1.00 | 0.0709 | 0.0718 | Pa05/Pa10 测 α=1: 0.066 |

> **在低尺度上训练，把 memory 位置的逐层更新又压下去了**：Pa10 在它自己的训练尺度上
> 从 0.204 掉到 0.1759（−14%），Pa05 从 0.273 掉到 0.2094（−23%）。
> 而 P₁（在 α=1 训练）拿到 α=0.10 去测反而是 0.2087，和未训练时一样。

**不是"训练没能把它抬上去"，是"训练主动把它压下去了"**，两条臂方向一致。

#### 结论：落在 §3.3 的「都不满足」分支

> **缩放这条路走完了。** 但失败的方式比"没效果"信息量大：
>
> 1. **decoder 完全学得会在低尺度上读 latent。** 零训练赤字 α=0.05 是 −0.135，训练后
>    收到 **−0.011**；α=0.10 从 −0.055 收到 −0.0145。**尺度变换可以被训练几乎无损吸收**
>    ——这正是 §2.1 预测的（RMSNorm 让读路径对尺度严格不变），现在有了训练侧的确认。
> 2. **但给了它"参与计算"的余地，它不要。** 三条判据里唯一能动的那个量，训练把它往
>    回推。
>
> 合起来：**"让 memory 位置被逐层加工"不是这个模型缺的东西。**
> §1.3 的**测量**仍然成立（latent 确实是只读 K/V），但把它读成**缺口的成因**的那一步
> 被证伪了。

#### 一个更重要的副产品：真正有效的是在域内训 LoRA

用**同一条 eval 路径、同样 2000 行**补跑冻结 decoder 的 P：

| P baseline（n=2000，同 harness） | substring | EM | F1 |
| --- | ---: | ---: | ---: |
| decoder 冻结（PISCO 发布权重） | **0.4850** | 0.0175 | 0.1603 |
| decoder LoRA 训 3000 步（= P₁） | **0.5990** | 0.5510 | 0.6775 |
| **Δ** | **+0.1140** | | |

（EM 从 0.018 跳到 0.551 主要是**格式**效应——冻结的 PISCO decoder 在 HotpotQA 上答得
啰嗦，EM 全判错；跨条件可比的是 substring。）

> **本轮所有架构想法里，效果最大的是"在目标域上训一下 decoder LoRA"，+11.4 点，
> 和任何表示/读出设计都无关。**

⚠️ **不能由此推出"压缩缺口被训练补上了"**：raw 的 0.625 是**冻结** decoder 在 n=200 上
测的，没有"训练后的 decoder 读原文"这个对照。要做这个比较必须先补那一格。
（顺带更正：先前口头说的"0.520 → 0.599 值 8 点"是跨 harness、跨 n 的无控制比较；
受控版本是 0.485 → 0.599 = +11.4 点，而 0.520 与 0.485 的差落在 n=200 的抽样噪声里。）

## 4. 方案 #2：压制成分是否可与文档信息分离

### 4.1 已有的分解证据

上一轮的 `mean` 干预给出 `Z_i = μ_row + Δ_i` 的分解读数：

| 干预 | 遵循率 | 重建 ROUGE-L |
| --- | ---: | ---: |
| 原样 | 0.225 | 0.616 |
| **全槽位取均值（留 μ_row，丢 Δ_i）** | **0.225（压制全留）** | 0.303 |
| 范数匹配随机方向（μ 和 Δ 都丢） | 0.625 | 0.118 |

**μ 承载压制，Δ 承载文档信息。** 于是"能不能只移走 μ"是一个有是非答案的问题，不是一个
设计选择。

### 4.2 latent 的语料级几何（8192 篇文档、65536 个 latent）

| 量 | 值 |
| --- | ---: |
| 单个 latent 的典型范数 | ≈ 104 |
| **语料均值 μ_global 的范数** | **56.41** |
| 最大奇异方向占二阶矩能量 | **47.5%** |
| 前 8 个方向占二阶矩能量 | 72.5% |

**每个 PISCO latent 有约 54% 的幅度是一个固定的、与文档无关的偏移**；整个分布是围绕单一
主方向的一个窄锥。这正是 SeleCom 理论里"正半空间"的定量版本——而且它说明
`8 × 4096` 的 cache 里，每篇文档独有的信息远少于名义维度。

### 4.3 扫描设计与判据

| 条件 | 去掉什么 | 留下什么 |
| --- | --- | --- |
| `global_mean` | 全部文档信息 | 只有 μ_global（互补检验） |
| `decenter` | μ_global | Δ（范数同时缩到 ≈87） |
| `decenter_renorm` | μ_global | Δ，**范数复原到 ‖Z‖**（把尺度混淆排除） |
| `deproject:k`，k ∈ {1,2,4,8,16} | 前 k 个主方向 | 其余，范数复原 |
| `mean`（参照） | Δ | μ_row |

每个条件**同时**测 conflict 与 reconstruct。判据：

- **可分离**：某个 k 上遵循率明显回升（→ raw 的 0.65 一侧）而 ROUGE-L 基本保持
  → 创新点成立：**"软压缩表示里导致指令压制的成分是一个低秩、query-无关的偏移，
  可在不损失文档信息的前提下移除"**。
- **不可分离**：遵循率和 ROUGE-L 一起掉（像 `norm_matched_random` 那样）
  → 同样是结果：**SeleCom 的 infeasible 在一个它自己没说的意义上成立**——压制与文档信息
  在表示层不可分。
- **`global_mean` 若单独就能压制**（遵循率 ≈ 0.225，而它不含任何文档信息）
  → 压制成分连 row-specific 都不是，是一个全语料共享的常向量。

两种结果都能写，这是这个实验相对 R / RQ 的关键区别：R / RQ 只有正结果才有意义，
所以零收益等于白跑。

### 4.4 结果：**不可分离**

n=40，两种脚手架各跑一次。下表为 SeleCom 脚手架（效应可测的那一套）；
`subspace-pisco` 形状相同，只是整体被脚手架压低（见 §4.5）。

**判据按 §4.3 逐条落实：**

1. **不可分离。** 没有任何 k：**九个干预里，Δ ROUGE-L 的 CI 无一含 0，全部严格为负，
   幅度 −0.31 ~ −0.52**；而 Δ 遵循率最多 +0.300，且一半的 CI 含 0。
   去掉 16 个主方向把遵循率推到 0.525（离 raw 的 0.650 仍有距离），代价是 ROUGE-L 掉到
   0.169——已经是 `none`（0.104）和 `mismatch`（0.126）的水平，**文档信息基本没了**。
   `figures/separability_tradeoff.png` 把这件事画成一张图：所有 latent 编辑都往左走。

2. **`μ_row` 是最锋利的一条：Δ 遵循率 = +0.000 [−0.100, +0.100]，Δ ROUGE-L = −0.312。**
   把 8 个槽位全换成它们的行均值，**压制一点不减，文档能力掉一半**。

3. **`μ_global` 的互补检验给出一个强结论**：一个**全语料共享的常向量**，不含任何文档信息
   （ROUGE-L 0.097 = `none` 的 0.104），遵循率却只有 0.375 —— 从 `none` 的 1.000 掉了
   0.625，即**压制的 81%（0.625 / 0.775）由这一个与文档、与 query 都无关的常向量承载**。

4. **但"加上 μ 会压制"不等于"减掉 μ 能解压制"**，这是本轮最反直觉的一点：
   μ_global 单独就能压掉 81%，可把它减掉只把遵循率从 0.225 抬到 0.375（回收 19%）。
   原因看 density 一列：**去中心之后 density 比值从 0.278 跳到 3.3–3.6、qk gap 从 −0.93
   跳到 +2.4**，latent 变成了注意力磁铁——和 `norm_matched_random` 落进同一个"奇怪向量"
   区域。移走那个方向并没有把 latent 变得更像 token，只是把它变成了另一种离群点。

5. **又一次 dominance↑ 与行为↑ 同向**：去中心让 density 比值涨 12 倍并越过 1，遵循率
   同时**上升**。与 SeleCom 的预测反号，与 §5.0 的 `memory@rand` 一致。

**结论按 §4.3 的第二个分支落地：**

> **SeleCom 的 *infeasible* 在一个它自己没说的意义上成立**——不是"注意力被压缩向量捕获"，
> 而是**在 PISCO 的表示里，引起指令压制的成分与承载文档信息的成分线性不可分**：
> 任何把前者移走的线性操作都会等比例带走后者，九种干预全部落在同一条权衡曲线上。

**但这条权衡是压缩表示特有的，不是任务固有的**：`raw` 同时拥有 ROUGE-L 0.916 与遵循率
0.650，**远在这条曲线之外**（见图）。所以"两者不可分"是当前 latent 几何的性质，不是
"文档信息必然带来压制"的普遍规律——这正是 §3 方案 #1 值得试的理由：它不动方向，只动尺度。

## 5. 三轮实验之后：「离线 cache 完全不变」这条约束该怎么改

### 5.1 这条约束其实在做两件事，只有一件是承重的

`docs/QURO_EXPERIMENTAL_DESIGN.md` 以来，"离线 PISCO cache 完全不变"一直是课题的地基。
但它同时锁定了两件**互相独立**的事：

| | 内容 | 是否承重 |
| --- | --- | --- |
| **A** | 文档表示**离线算、每篇一次、与 query 无关、可复用** | **承重**。这是 QuRO 相对"每次重编码"的全部效率主张 |
| **B** | 这个表示**必须是 PISCO 发布的那批 latent**（它的目标、它的几何、它的逐文档独立性） | **不承重**。这是继承来的，不是推导出来的 |

**本轮测到的所有损害都落在 B，A 一条没被触及**：

- latent 残差范数 104，32 层几乎不动（§1）→ PISCO 的 projection MLP 定的值域
- 每个 latent 约 **54%** 的幅度是与文档无关的固定偏移，最大主方向占 **47.5%** 能量（§4.2）
  → 名义 `8 × 4096` 的容量有一大半花在一个所有文档共享的常量上
- 压制成分与文档信息**线性不可分**（§4.4）→ PISCO 目标塑造出的几何
- **每篇文档独立压缩**，没有任何 latent 见过别的文档（§2.2）→ PISCO 的压缩粒度

> **结论：约束应该拆开。保留 A（离线、query-agnostic、per-document、可复用），
> 放弃 B（必须是 PISCO 那批 latent）。**

这不是放松 QuRO 的主张，而是**把主张还原到它真正需要的那一半**。三条读出臂
（A1/C1、R、RQ）加上本轮的 Pα，四次都在 B 给定的前提下改 online 侧，四次为零——
这本身就是"该动的不是 online 侧"的证据。

### 5.2 但在换 cache 之前，必须先排除一个替代解释

§2.2 把全部缺口定位到 bridge 题（−0.137），我把它读成"**不能跨文档组合**"。
**还有一个同样合身的解释没排除：bridge 题需要一个具体的桥接实体名，而 16:1 的压缩
可能就是没保住那个稀有词——那是信息丢失，不是组合失败。**

两者指向完全不同的方案（前者要让文档互相看见，后者要提高单篇保真度），所以必须先分开。
两个都便宜：

1. **K=2 oracle**：只给 gold 的两篇文档（而不是 10 篇），memory vs raw，分 bridge/comparison。
   排除"选择/检索"这个混淆——若 K=2 下 bridge 仍然落后，就不是选错了文档。
2. **桥接实体召回率**：从 latent 重建出的文本里，桥接实体（gold 支持句里连接两篇文档的
   那个专名）出现的比例，对比非桥接的其它实体。
   - 桥接实体**保住了**却答不对 → 组合失败，方向见 §5.3 第 1 条
   - 桥接实体**被选择性丢掉** → 信息丢失，方向见 §5.3 第 2 条

**这两个实验都不训练，几小时内能出，且两种结果都能写。应该排在任何新方案之前。**

### 5.3 可能的方向（按证据强度排）

#### 方向 1：离线阶段就让文档互相可见，但保住 per-document 可复用性

**观测**：全部缺口在 bridge；每篇文档独立压缩，进了 decoder 又不演化，组合只能发生在
少数几个 reader 位置。

**难点**：直接让 K 篇文档互相看见就破坏了 A —— 组合数是 O(N²)，不能缓存。

**可行的形态**：仍然逐文档压缩，但**额外离线缓存一层"可组合的索引"**（文档级实体/关系
摘要），在线时用它把两篇的 latent 接起来。这仍然是离线、query-agnostic、每篇一次。
门槛是它必须比"直接把 gold 两篇原文塞进去"便宜得多，否则不如不压。

**前置**：必须先过 §5.2，否则方向可能整个是错的。

#### 方向 2：换压缩目标，而不是换读出 —— 直接攻击已测到的浪费

**观测**：54% 的幅度是固定偏移，47.5% 的能量在单一方向上。**这是可量化的容量浪费。**

**动作**：重训压缩器（或只重训 projection MLP，代价小得多），目标里加去中心化/白化或
逐文档对比约束，让 per-document 的信息在 8 个 latent 里占更大比例。
**Job A 完全保留**——还是离线、query-agnostic、每篇一次。

**判据**（同样 8 个 latent、同样 cache 大小）：语料均值范数从 56.4 降下来；重建 ROUGE-L
与 bridge QA 上升。**这条的好处是它有一个事先可测的中间量**，不用等下游指标才知道有没有
动静。

**这是我认为最值得先做的训练类方向**：它攻击的是一个已经量化的缺陷，而不是又一个结构猜想。

#### 方向 3：改 adapter 的训练分布（最便宜，不动 cache）

**观测**：LoRA 给 raw/空槽位 +0.65/+0.55 的指令遵循，给 memory +0/−0.125（§5.2 of
上游文档）；而 Stage C 显示训练**主动降低**了 memory 位置的上下文化（§3.4 判据 ③）。
两条合起来说明 decoder 学到的是"把 memory 当只读表查"，而且它**偏好**这样。

**动作**：在训练分布里混入**必须跨 latent 组合**才能答对的样本，看 decoder 是否学会在
memory 位置做计算（重测 §1 的相对更新）。

**注意这条的先验不乐观**：Stage C 已经表明，在有余地的时候模型选择了不组合。但那是在
**没有任何监督压力**要求它组合的情况下。这条正是补上那个压力。

#### 方向 4：接受 comparison 平价，把课题重新定位

**观测**：comparison 题上 PISCO memory **0.692 vs 原文 0.667（+0.026 [+0.000, +0.077]）**，
而 prefill 从 1126 token 降到 159 token。

**在不需要跨文档组合的任务上，~14× 的压缩是免费的，甚至更好。** 这是本轮唯一带正号的
结果，而且有机制解释（每篇文档独立供一个事实，正好是逐文档压缩能做好的形态）。

课题可以重新定位成"**刻画软压缩的适用边界**"：什么样的 query-文档结构下压缩无损、
什么样的下必然有损、界在哪。这不是退缩——**这是目前手上证据支持得最充分的一篇**，
而且前三个方向不管成不成，这个刻画都成立。

### 5.4 应该停止的方向

- **不要再做 readout 结构。** A1/C1、R、RQ、Pα 四次零边际，且本轮给出了机制解释：
  online 侧改的是"从一张静态表里读什么"，而缺口在这张表**本身**。
- **不要再做注意力校准 / gate / logit bias / K 范数匹配。** 上游文档 §3、§5.1 已证明
  这些动作作用的量与失败无关，人为拉高它行为反而变好。
- **不要再用推理时的线性手术去分离压制成分。** §4.4 的九种干预全落在同一条权衡曲线上。

### 5.5 一个必须补的对照

§3.4 测到"在目标域上训 decoder LoRA 值 **+11.4 点** substring"（0.485 → 0.599，n=2000，
同 harness）——**这是本轮所有干预里效果最大的一个，和任何表示设计都无关**。

但由此**不能**推出"压缩缺口被补上了"：raw 的 0.625 来自**冻结** decoder、n=200。
**必须补"训练后的 decoder 读原文"这一格**，否则 §0 的 10.5 点这个靶子本身就是在两个
不同系统之间测的。这是下一步最优先的一次评测，成本很低。
