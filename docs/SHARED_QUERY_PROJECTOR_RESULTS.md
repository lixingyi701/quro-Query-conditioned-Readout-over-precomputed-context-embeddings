# 共享文档投影器首轮结果（2026-10-03）

**一句话结论：** 冻结发布版 PISCO、只训投影器的条件下，F1 从 16 涨到 64。这部分
涨幅来自答案格式，完全不看问题的 S0m 也能拿到。问题条件化的额外收益，在全量
test 上是 SQ +0.62 F1、SQX +0.85 F1，在之前没评估过的 3405 条上只有约 +0.3（不
显著），dev 上是 0，**未确立**。投影器确实在读问题：只给它换一个错误的问题，F1 掉
约 1.05 个点，置信区间不含 0。但问题信息能带来的作用总共只有大约 1 个点。

代码：`feat/pisco-joint-query-projector@1610106`，设计见
[SHARED_QUERY_PROJECTOR.md](SHARED_QUERY_PROJECTOR.md)。运行输出在
`/data02/quro/runs/shared_projector_v1/`（启动脚本与日志在 `logs/`）。本文所有
表格由 `python scripts/analyze_shared_projector.py` 生成，原始输出存于
`analysis/all_tables.txt`。

## 1. 各臂到底是什么

**所有臂的共同设置**（来自 `--preset pisco_shared_projector`）：

- **reader**：发布版 PISCO-Mistral（`/data02/quro/models/pisco-mistral`，7B 底座为
  Mistral-7B-Instruct-v0.2）。encoder、decoder、两组 LoRA、词嵌入、LM head 全部
  冻结，`decoder_adapter` 保持激活。
- **文档**：HotpotQA，每题 K=10 篇检索文档。文档读的是离线缓存
  `/data02/quro/cache/hotpot-pisco-r16`（压缩率 16，每篇截到 128 token，所以每篇
  m=8 个 memory，共 80 个）。训练时不在线压缩。
- **预算**：每篇 8 个 memory 进、8 个出，不做筛选，decoder 看到的 memory 数和发布版
  直接读缓存完全相同（80）。
- **注入方式**：投影后的 E 替换 D0 模板里 memory 位置的输入层 embedding，顺序是
  memory 在前、完整问题文本在后。问题文本一直原样给 decoder。
- **投影器通用结构**（每篇共用一套权重，与 K 和问题长度无关）：
  `C_i = 条件向量(Z_i, 问题)`，`U_i = GELU(Wz·vec(LN Z_i) + Wc·vec(LN C_i) + b1)`，
  `E_i = Z_i + reshape(Wo·U_i + b2)`。MLP 隐藏层 r=512，`Wo`/`b2` 零初始化，所以
  第 0 步 E=Z，和发布版逐位一致（已验证，见第 2 节）。
- **训练**：只用 gold 答案的 teacher-forcing CE（含 EOS），AdamW、lr 5e-5、5%
  warmup 后线性衰减、梯度裁剪 1，batch 2 × 累积 8 = 每步 16 条，3000 步（48k 条，
  约 1.6 遍 30k 训练集），seed 42，单 seed。每 250 步在 dev 前 500 条上验证，按 EM
  选 best。
- **评估**：除特别说明外，都是 **last checkpoint（第 3000 步）**，贪心解码，最多 32
  个新 token。

**各臂差异：**

| 代号 | 目录 / tmux | 问题怎么进投影器（条件向量 C_i 怎么来） | 跨文档 | 可训练参数 | 和 SQ 相比只改了 |
|---|---|---|---|---:|---|
| **base** | `published_direct` | 无投影器，发布版 PISCO 直接读缓存 | — | 0 | 不训练，`--readout pisco_direct --eval_only` |
| **S0m** | `shared_agnostic` | **不看问题**。用固定的 4 个随机向量（seed 0，与问题无关）替代问题 token，走和 SQ 完全相同的 attention 和 MLP | 否 | 37.78M | `--projector_query_mode agnostic_matched` |
| **SQ**（主臂） | `shared_contextual` | 问题单独过一遍冻结 decoder，取**所有问题 token** 的最后一层 hidden；每个 memory token 作 Q，问题 token 作 K/V，做 8 头 cross-attention（d_a=256） | 否 | 37.78M | — |
| **SQX** | `shared_crossdoc` | 同 SQ | **是**：在 U_i 上加一层文档间 self-attention（8 头，无文档位置编码，对文档顺序置换等变） | 38.83M | `--projector_cross_document` |
| **SL** | `shared_last` | 同样是冻结 decoder 的问题前向，但**只取最后一个有效 token** 的 hidden h_q，经 value 投影后广播给每个 memory，不做 attention | 否 | 35.68M | `--projector_conditioning last` |
| **SW** | `shared_word` | 不做问题前向，用冻结 decoder 的**原始词嵌入**，加上无参数的 sinusoidal 位置特征，再做和 SQ 一样的 cross-attention | 否 | 37.78M | `--query_encoder_kind word_embedding` |

S0m 和 SQ 的参数量、结构、训练设置完全相同，唯一差别是投影器拿不到真实问题，所以
**SQ − S0m 就是"问题条件化"的边际**。SL 少了 attention 的 Q/K 矩阵，参数稍少，不
是严格的参数匹配对照。

**控制条件**（评估时设置，不重新训练）：

| 名称 | 投影器看到的问题 | decoder 看到的问题 | 文档 | 用来检验 |
|---|---|---|---|---|
| normal | 正确 | 正确 | 正确 | — |
| mismatch-q | **换成别的题的问题** | 正确 | 正确 | 投影器是否依赖问题 |
| mismatch-q-both | 换 | 换 | 正确 | decoder 是否依赖问题（不能单独归因于投影器） |
| mismatch-doc | 正确 | 正确 | **换成别的题的文档** | 是否依赖文档 |

## 6. 分析与观察

1. **48 个 F1 点的涨幅是格式收益。** base 有 72% 的回答写满了 32 token 的生成上限
   （平均 28.5 token，完整句子），S0m 平均 4.1 token。EM 和 F1 对长句惩罚很重，所以
   S0m 在 EM/F1 上从约 1/16 涨到 51/65。substring 的 +5.4 个点也主要来自截断：S0m
   比 base 多答对 357 题、少答对 249 题，多答对的里有 282 题是 base 被截断的。这些
   都和问题条件化无关。

2. **问题条件化的边际很小，且没有确立。** 全量 test 上 SQ +0.62、SQX +0.85 F1 的
   区间勉强不含 0。但在之前没评估过的 3405 条上只有 +0.3（不显著），dev 上是 0。
   第一轮看到的 +1.1/+1.7，主要是前 2000 条恰好偏高。再考虑到 SQ 和 SQX 是从四个臂里
   挑出来做全量评估的，合理估计是 0 到 0.6 F1。按事先定的门槛（全量 test 上 +1 个点
   仍然成立才补 seed），不补 seed。

3. **投影器确实在读问题，但作用总共约 1 个点。** 换问题让 SQ/SQX 掉约 1.05 F1，
   区间明确不含 0。这修正了第一轮"几乎不依赖问题"的说法。读法是：正确问题比不看
   问题高约 0.6，错误问题比不看问题低约 0.2 到 0.45（不显著），两者合起来大约 1 个
   点。问题信息被用上了，只是能撬动的空间小。

4. **问题表示的几种选法分不出高低。** SQ（全部 token + attention）、SL（只用 h_q）、
   SW（词嵌入 + 位置）相对 S0m 都在噪声内，test 前 2000 条上排序 SQ ≈ SW > SL，dev
   上全是 0。本轮数据不支持"上下文化 token 优于 h_q 或词嵌入"的说法，也不支持相反
   说法。

5. **跨文档 attention 的子组模式只是假设。** SQX 在 bridge 题上 +1.06 F1
   [+0.33, +1.80]，与"投影层做跨文档融合有助于多跳"的动机吻合。但这是事后才挑出
   的子组，dev 上 bridge 只有 +0.10，没复现。SQ 在 comparison 题上 +1.77 同样没在
   dev 复现（dev 上 −0.39）。如要检验，应把"SQX − S0m，只看 bridge，看 F1"作为
   唯一的预注册比较，在没用过的数据上做。

6. **换文档后各臂都还能拿到约 28 F1，base 只有 4.9。** 学会短答之后，模型单凭问题
   和参数知识也能答对一部分，各臂之间没有区别。问题和文档都换掉（mismatch-q-both）
   时全部降到约 1.5，说明 decoder 读的问题文本才是主要的信息来源之一。

7. **训练动态。** 验证曲线在约 1250 步后就进入 ±1 个点的平台（dev 500 条 F1 约
   63 到 66），训练 loss 在前 150 步就从约 2.8 降到 0.5 到 0.8，S0m 和其他臂一样快，
   与第 1 点一致。按 EM 选出的 best 落在 1500 到 3000 步不等（S0m 2750、SQ 1500、
   SQX 2500、SL 1750、SW 3000），但 dev 500 条的 EM 噪声约 ±2 个点，所以本文统一用
   last checkpoint。

## 7. 局限

- 每臂单 seed（42），seed 之间的波动没测，可能和 0.5 个点的效应同量级。
- dev 只评估了 2000 条，SL/SW 没做全量 test。
- 没有评估 best checkpoint，也没有做 K=2 评估。
- 训练耗时不可比：GPU0 同时跑 SQ 和 SW，GPU1 同时跑 S0m 和 base 评估，所以 SQ 用了
  8462 秒，S0m 只用了 5296 秒，这反映的是 GPU 共享，不是方法本身的开销。
- 格式收益让 EM 的绝对数字很容易误读：任何和 base 的比较都应以 S0m 为参照，不能以
  base 为参照。
